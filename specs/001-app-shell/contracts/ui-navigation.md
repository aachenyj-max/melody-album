## 主要跳转

01 创建按钮／底栏加号 → 02；02 添加／继续 → 03；03 确认 → 04；04 进入播放 → 05；05 调整 → 06，保存热点 → 07，返回 → 04；06 发送／重新播放 → 05；07 保存 → 08，稍后 → 05；08 首个相册卡片和其播放图标 → 09；09 修改音乐 → 当前相册的 06 调整状态（`/memories/[id]?state=adjust`），确认后返回当前 09，返回 → 08。

完整的 17 个热点（原始百分比坐标、名称、目标序号）保存在 components/music-album/design-map.ts 的 prototypeHotspots。实际 DOM 操作承担跳转，不覆盖透明全屏热点。SDD-02 中 02 的添加/继续操作必须先有 1–9 张有效照片并提交理解；03 的确认必须先有符合最低内容要求的 Memory Profile。

05 PNG 右侧按钮写“查看 AI 理解”，HTML 同一位置的热点称“保存相册”并进入 07。SDD-04 保留 PNG 可见文案：仅当前会话存在已验证可播放的 AI 或 QQ 音乐版本时，该热点进入 07；只有通用等待音或音频失败时禁用。AI 理解改由播放画面上的独立上拉区域展开，不重启音乐。05 左上返回 04 时停止声音；05→06 暂停声音；06 发送指令时留在 06 展示生成中/成功/失败，成功后点击音乐卡“重新播放”进入 05。07 的保存写入由 SDD-05 实现。具体运行前提见 `components/music-album/design-map.ts` 的 `playHotspotPreconditions`。

首页和列表显示五项底栏，只有首页、创建、记忆有路由；音乐和个人中心为 disabled。未知相册 ID 使用 App Router notFound 和可返回列表的中文状态。演示保存仅导航，不落库。页面没有 Supabase 业务请求；原有会话代理边界不变。

## 2026-10-09 用户明确更新 09 详情与调整行为

用户要求详情下半部分由推荐歌曲改为相册照片，底部“生成音乐”改为“修改音乐”；已选择“生成候选→试听→确认替换，取消/失败保留原音乐”的方案。本条覆盖 09 原始 HTML/PNG 中对应内容和跳转。

- 09：展示当前相册全部照片的三列网格，可滚动，点击放大并切换前后照片，关闭后留在详情。
- 09 修改音乐 → `/memories/[id]?state=adjust`，沿用 06 调整画面的视觉语义，携带已保存相册与当前音乐，支持直接打开/刷新，不依赖创建临时会话。
- 发送自然语言要求时留在调整页，真实 ACE-Step 生成候选，不更换相册当前音乐。试听前确认按钮禁用；音频元数据有效并实际开始试听后可确认。
- 保留原音乐/取消生成不修改相册；确认后返回同一相册 09。失败显示原因并保留原版本。真实相册使用服务端原子确认，旧版本保留；音乐已被另一页面修改时返回冲突，不能覆盖。演示相册仅当前浏览器确认保存，也保留旧版本。
- API：`POST /api/albums/[id]/music` 生成候选，`PATCH /api/albums/[id]/music` 确认已生成版本。禁止从客户端提交音频 URL 作为真实相册的确认结果；只接受该相册已有候选版本。原 `/play?state=adjust` 创建中调整流程保持原契约。
