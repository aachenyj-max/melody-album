# 失败与重试验收

日期：2026-10-06。使用开发环境显式 demo 故障注入；真实 `FAL_KEY` 保持在本地文件中，故障服务器进程将其覆盖为空值，未提交新付费请求。

| 场景 | 实测 |
| --- | --- |
| AI 失败 | `FAL_DEMO_SCENARIO=error` 返回 HTTP 502 / `PROVIDER_ERROR`；04 显示“原创配乐暂未完成”和“重试原创配乐”，已验证的 QQ 演示推荐仍在。未选推荐时“进入播放”被阻止。 |
| 失败后选择 QQ | 点击“轻轻告别（演示）”后，“进入播放”可用；05 显示 QQ 音乐演示推荐。 |
| QQ 空列表 | 开发会话设 `sdd03:recommendations=empty`，04 显示“暂无可播放的演示推荐”，AI 同时失败时不能进入空音源播放。 |
| 仅有元信息 | 设 `sdd03:recommendations=metadata` 后重新加载，三张卡可读但均不可选；AI 失败时“进入播放”仍被阻止。 |
| QQ 失败 | 设 `sdd03:recommendations=failed`，04 显示“推荐暂不可用，请重新加载”，AI 分支错误保持独立。 |
| 新创作废弃旧请求 | 45 秒慢响应期间离开结果页并开始“新记忆 B”；旧浏览器请求中止，新页仍显示 B 的等待状态，随后 05 显示“新记忆 B”，没有被旧运行覆盖。 |

路由还验证了含额外照片 URL、90 秒时长、过短提示词的请求均返回 HTTP 400 / `INVALID_PROFILE`。推荐可播标志只在浏览器加载音频元数据成功后设置。
