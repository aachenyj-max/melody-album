# 等待与跨页播放验收

日期：2026-10-06。环境：本地 Next.js 开发服务器、Chromium，375 × 844。

| 场景 | 实测 |
| --- | --- |
| 真实 MiniMax 排队 | fal.ai `fal-ai/minimax-music/v2.6` 返回排队任务，约 2.9 分钟后 `COMPLETED`；浏览器加载返回音频并显示 `source=api` 的 28 秒试听。等待时页面不显示虚构百分比。 |
| 慢响应跨页 | 显式 demo 适配器延迟 45 秒；04 显示“正在生成”，进入 05 后显示“记忆的氛围 / 等待中的氛围音乐”；完成后同一播放页切为“青春的回声（演示配乐） / AI 演示配乐”。 |
| 主动选 QQ | 在 AI 仍等待时点选可播的“轻轻告别（演示）”，05 显示 QQ 音乐演示推荐；45 秒后 AI 完成仍显示 QQ，未抢占选中音源。 |
| 自动播放受阻 | 在浏览器中模拟 `HTMLMediaElement.play()` 拒绝，点选 QQ 后 05 显示“点击播放”，未误报播放中。 |

音频由 `MusicSessionProvider` 中唯一的 `audioRef` 控制，切换前调用 `stop()`；代码检查未发现并行活动播放器。浏览器自动化无法主观听音，因此叠音结论基于单播放器实现与页面状态，仍可在用户验收时听音复核。
