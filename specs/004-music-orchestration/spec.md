## Clarifications

### Session 2026-10-05

- Q: AI 原创失败时，如果 QQ 音乐只返回歌曲信息、没有可合法播放的音频，用户应如何继续播放？ → A: 只有可播放的 QQ 歌曲才能作为播放兜底；否则提示重试。当前 Demo 无法连接 QQ 音乐曲库，使用明确标识的 mock 推荐数据。
- Q: 当前 Demo 的 AI 无歌词配乐能否调用真实生成服务？ → A: 目标是调用真实文字生成音乐 API；用户稍后提供接入资料。在资料到位前可用明确标识的演示适配器验证流程，真实生成验收必须等待 API 接入。
- Q: AI 配乐仍在生成时，用户点击“进入播放”，默认应听到哪段音乐？ → A: 默认继续播放氛围音乐，AI 配乐完成后切换；只有用户主动选择 QQ 音乐推荐时才播放推荐。

## User Scenarios & Testing

### User Story 1 - 从确认的记忆得到两路音乐结果 (Priority: P1)

用户确认照片的记忆理解后，在“为你生成”结果页看到专属无歌词配乐的状态和 QQ 音乐推荐。当前 Demo 的推荐使用 mock 数据并明确标识。两路内容共享同一份记忆的音乐意图，用户能分辨来源并进入后续播放。

**Why this priority**: 这是记忆理解与首次播放之间的核心交接，也体现“创造音乐”和“找到音乐”的并列价值。

**Independent Test**: 用已确认的毕业记忆进入结果页，验证音乐意图与记忆相符、至少一首标明“演示推荐”的 mock 歌曲可见、AI 配乐状态明确，点击主按钮能进入播放页；真实生成能力在用户提供 API 后另行验收。

**Acceptance Scenarios**:

1. **Given** 用户已确认有效的记忆理解，**When** 用户进入结果页，**Then** 只消费该确认版本，启动无歌词配乐与 QQ 音乐推荐，不消费仍在修正或已失效的结果。
2. **Given** 真实文字生成音乐 API 已接入且两路结果均成功，**When** 用户浏览结果页，**Then** 页面并列呈现“为你生成”和“QQ音乐推荐”；AI 配乐目标时长为 15–30 秒，至少一首标明“演示推荐”的 mock 歌曲显示封面、歌名、歌手、时长与简短推荐理由。
3. **Given** 真实文字生成音乐 API 尚未提供，**When** 用户演示结果页，**Then** AI 配乐路径显示“演示配乐”身份，并能展示等待、成功或失败状态；不得称其为真实生成。
4. **Given** AI 配乐已完成或仍在生成且等待音乐可播放，**When** 用户保持“为你生成”选中并点击“进入播放”，**Then** 进入 05 号播放页并交接照片与 AI 状态；生成期间先接续氛围音乐，完成后切换为 AI 配乐，且不得将等待音乐标作成品。
5. **Given** 用户主动选中一首可播放的 QQ 音乐 mock 推荐，**When** 用户点击“进入播放”，**Then** 进入 05 号播放页并播放该推荐；仅切换浏览区域而未选择歌曲时不改变默认 AI 路径。

### User Story 2 - 在生成期间听到音乐并了解进展 (Priority: P1)

个性化配乐需要等待时，用户仍能看到照片与推荐，并可听到与记忆氛围相符的通用氛围音乐。完成后，个性化配乐取代等待音乐。

**Why this priority**: 等待不能成为空白页面，首次听到符合记忆氛围的声音是本阶段的重要体验。

**Independent Test**: 延迟个性化配乐响应，核对等待提示、进度、氛围音乐与推荐的独立更新；再完成配乐，检查音源切换。分别检查设备允许与阻止自动播放的情况。

**Acceptance Scenarios**:

1. **Given** AI 配乐仍在生成，**When** 用户停留在结果页，**Then** 页面持续显示可理解的生成状态和轻量进度，提供通用氛围音乐，推荐区域独立更新。
2. **Given** 等待音乐已经开始播放，**When** 个性化配乐可用，**Then** 等待音乐平顺退出、个性化配乐接续，不出现两段音频同时播放。
3. **Given** 设备阻止自动播放，**When** 等待状态出现，**Then** 页面提供由用户触发的播放操作，且不误报“正在播放”。
4. **Given** 服务没有提供可信百分比，**When** 页面显示进度，**Then** 使用进行中或预计等待文案，不固定显示原型示例中的“60%”。
5. **Given** 用户在 AI 配乐生成期间进入 05 号播放页，**When** 生成完成，**Then** 播放页接续当前等待音乐并切换到 AI 配乐；用户主动选择推荐时不发生 AI 音源自动抢播。

### User Story 3 - 原创失败仍能继续使用推荐 (Priority: P1)

如果 AI 原创失败或超时，用户仍能查看已得到的 QQ 音乐推荐，重试原创，或继续前往播放与后续保存流程。

**Why this priority**: 单一路径故障不能毁掉用户已经完成的照片和记忆创作。

**Independent Test**: 令原创失败而 QQ 音乐 mock 推荐可播放，确认推荐不消失、重试可用、播放入口有效，且推荐结果可交给后续保存阶段。

**Acceptance Scenarios**:

1. **Given** mock 推荐中有可播放歌曲，**When** AI 原创失败或超时，**Then** 推荐与照片仍可见，原创显示失败和重试；用户主动选择该推荐后仍能进入播放并在 SDD-05 中保存。
2. **Given** 原创失败后用户重试，**When** 新一轮生成开始，**Then** 推荐保持可见；再次失败也不清除推荐。
3. **Given** 推荐失败但 AI 配乐可用，**When** 用户浏览结果，**Then** AI 配乐仍可进入播放，推荐区域显示独立失败和重试。
4. **Given** 原创失败且推荐歌曲只有元信息、没有可播放音频，**When** 用户查看结果页，**Then** 页面保留推荐信息并提示重试，不允许以空音源进入播放。

### Edge Cases

- 直接打开或刷新 `/result` 时没有本次已确认记忆：显示明确空状态和返回创建入口，不用历史 mock 冒充当前结果。
- 已确认记忆缺少有效事件和氛围：不发起音乐编排，提示返回修正记忆。
- 两路先后完成：先完成的一路立即可见；旧轮次或过期响应不能覆盖重试后的新结果。
- mock 推荐返回空列表、缺少封面或缺少可用音频：显示空状态或封面占位；无音频的歌曲不能标为可播放，也不能作为原创失败后的播放兜底。
- 氛围音乐资源失效：保留进度和两路结果，用户仍能等待或选择已可用音乐。
- 用户以默认 AI 路径进入播放后，原创生成失败：结束等待音乐，提示重试或主动选择可播放推荐；不得无限播放等待音乐并声称原创即将完成。
- 用户离开或开始新创建：停止当前播放，旧请求结果不能写入新记忆，也不能误认为相册已保存。
- 快速重复点击播放或重试：不得导致音频重叠、重复导航或旧结果覆盖。
- 窄屏与较大系统字体下，两路区域、状态和主按钮保持可阅读、可操作。

## Requirements

### Functional Requirements

- **FR-001**: 结果编排 MUST 只接受 SDD-02 已确认的有效记忆理解和对应照片；无有效交接时 MUST 显示空状态与返回入口。
- **FR-002**: 系统 MUST 从确认的记忆提炼音乐意图，至少覆盖情绪、风格、节奏和结构；没有依据的项目 MUST 保持中性或未指定。
- **FR-003**: 系统 MUST 针对同一音乐意图独立获取 15–30 秒无歌词 AI 配乐和 QQ 音乐推荐，分别追踪等待、成功和失败；AI 配乐的正式来源 MUST 是用户将提供的真实文字生成音乐 API，QQ 音乐推荐在当前 Demo MUST 使用明确标识的 mock 数据。
- **FR-004**: 推荐成功时 MUST 至少展示一首标明演示来源的 mock 歌曲，包含封面或占位、歌名、歌手、时长、推荐理由；可播放状态 MUST 由实际可用的音频资源决定。
- **FR-005**: 结果页 MUST 按 04 号 PNG 呈现标题、生成状态区、两路音乐展示区、AI 配乐卡、推荐卡及底部“进入播放”按钮，并保持 HTML 的 03→04→05 主要跳转和视觉层级。
- **FR-006**: AI 配乐等待期间 MUST 提供与记忆氛围相符的通用氛围音乐和轻量进度；设备未授权音频播放时 MUST 如实显示未播放并提供手动启动操作。
- **FR-007**: 只有收到可信进展信息才能显示精确百分比；否则 MUST 使用不确定进度或预计等待文案。
- **FR-008**: 个性化配乐成功后 MUST 更新音源和状态；在用户保持 AI 路径且等待音源正在播放时 MUST 平顺切换，避免重叠和明显突兀中断；用户已主动选择推荐歌曲时 MUST 保持该选择，不得自动抢播 AI 配乐。
- **FR-009**: 原创失败或超时时 MUST 保留 QQ 音乐 mock 推荐并提供失败提示和重试；只有推荐歌曲实际可播放时，才能基于它进入播放和后续保存，否则 MUST 提示重试。
- **FR-010**: 推荐失败或为空时 MUST 保留已成功的 AI 配乐并提供独立反馈和重试；两路均不可用时 MUST 阻止无音源播放。
- **FR-011**: 结果页 MUST 保持确认记忆、照片、音乐意图、结果和来源的关联，不得将等待音乐或失败响应标作已完成 AI 配乐。
- **FR-012**: 重试或离开流程时 MUST 防止旧响应覆盖当前状态，并停止不再需要的等待音频。
- **FR-013**: 当前 Demo 的 QQ 音乐推荐 MUST 使用稳定的 mock 数据与可验证的播放资源，并显示“演示推荐”；后续接入真实曲库前，MUST 另行确认其输入、输出、可播放条件、失败类别和重试规则，mock 结果不能计入真实曲库验收。
- **FR-014**: 在真实文字生成音乐 API 的接入资料和凭证到位前，AI 路径 MAY 使用与预期状态一致的本地演示适配器，但 MUST 清楚标明“演示配乐”；只有接入真实 API 并验证生成音频后，才能认定 AI 配乐的正式验收通过。
- **FR-015**: 04 号页默认选中“为你生成”。AI 配乐仍在生成且氛围音乐可播放时，“进入播放” MUST 进入 05 号页并接续氛围音乐，完成后按 FR-008 切换；只有用户主动选中可播放的 QQ 音乐推荐，才能以推荐歌曲作为进入播放的音源。

### Key Entities

- **已确认记忆**：SDD-02 交付的有效标题、事件、氛围、人物/时间线与照片顺序，是音乐编排的唯一输入版本。
- **音乐意图（Music Profile）**：从已确认记忆提炼的情绪、风格、节奏和结构，关联原记忆。
- **音乐生成轮次**：对同一音乐意图发起的一次双路尝试，记录各自状态、失败类别和重试关系。
- **AI 配乐结果**：无歌词个性化音频及标题、时长、可播放状态和来源；失败时没有伪造音频。
- **QQ 音乐推荐**：当前 Demo 中为明确标识的 mock 歌曲，包含识别信息、推荐理由与可播放条件；真实曲库接入留待后续。
- **等待音乐**：生成期间使用的通用氛围音乐，不等同于个性化配乐。
- **当前音乐选择**：默认 AI 配乐路径，或用户主动选中的可播放 QQ 音乐推荐；决定进入播放页时的音源及后续是否自动切换。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 已确认的演示记忆进入成功场景时，每次都能在 04 号页看到 AI 配乐状态和至少一首标明演示来源的 QQ 音乐 mock 推荐，并在 AI 配乐、等待音乐或所选推荐可播放时于 2 次点击内进入播放页；API 到位后的正式验收必须使用真实生成的 AI 音频。
- **SC-002**: 成功、慢响应、原创失败三组场景均可完整演示；慢响应期间始终有明确等待说明，且用户能启动等待音乐。
- **SC-003**: 原创失败而 mock 推荐有可播放音频的 10 次重复演示中，10 次均保留推荐并允许进入播放，后续保存入口不受原创失败阻断；推荐只有元信息时，10 次均阻止空音源播放并提示重试。
- **SC-004**: 个性化配乐成功的 10 次演示中，10 次均从等待状态更新为可播放配乐；等待音乐播放时，切换期间无音频重叠。
- **SC-005**: 在至少 3 个常见移动宽度下，04 号界面的布局、层级、配色、字体、图片位置、按钮文案与 PNG 一致，主要跳转与 HTML 一致，且无明显横向溢出。
- **SC-006**: 至少 90% 的评审者仅看结果页，就能在 30 秒内区分 AI 原创、QQ 音乐推荐和等待音乐，并指出当前是否已有个性化配乐。
- **SC-007**: AI 配乐延迟完成的 10 次演示中，保持默认 AI 路径进入播放的 10 次均先接续等待音乐再切换到 AI 配乐；主动选择可播放推荐的 10 次演示中，10 次均不发生 AI 完成后抢播推荐音源。

## Assumptions

- “第3阶段”指 `progress.md` 的 SDD-03，承接 SDD-02 的已确认 Memory Profile，主要负责 04 号结果页与音乐结果交接。
- 当前 Demo 无法连接 QQ 音乐曲库，由用户明确指定使用 mock 推荐。mock 曲目须标明演示来源且有可验证的可播放状态；真实曲库接入与真实检索验收不属于本次 Demo。
- 用户后续提供文字生成音乐 API 的接入资料；在此之前可用标明身份的演示适配器验证 UI 和状态，但真实生成验收保持未完成。API 的请求、响应、错误语义及可播放资源条件须在接入时据实确认。
- 结果在当前创作流程中临时存在；相册持久化及刷新后找回由 SDD-05 负责。直接打开或刷新结果页无交接时显示空状态。
- 等待音乐需要可合法使用的通用音频素材；设备阻止自动播放时由用户主动启动。
- 本阶段负责向 05 号播放页交接正确的照片、当前音乐选择、等待/完成状态与可用音源；05 号页实际的播放控制、照片切换和自然语言调整由 SDD-04 完成，保存写入由 SDD-05 完成。

## Out of Scope

- 重新理解照片记忆或修改已确认的照片集合。
- 05–06 号完整沉浸式播放、自然语言调整和多个 AI 版本对比。
- 07–09 号保存、持久化与历史数据写入。
- 歌词、人声、完整歌曲、真实分享、自动事件归档与个人音乐偏好接入。
