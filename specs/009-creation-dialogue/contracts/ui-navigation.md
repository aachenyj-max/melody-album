# 02/03 连续对话的视觉与导航覆盖

2026-10-09 用户明确确认。原型 [全局导航](../../001-app-shell/contracts/ui-navigation.md) 和 PNG 继续约束外壳、色彩、标题、照片和既有页面顺序；以下局部替换在实现阶段同步回全局契约、design-map.ts 和 AGENTS.md。

| 区域 | 保留基线 | 本次明确变更 |
|---|---|---|
| 02 初始 | 手机外壳、创建音乐相册标题、拼贴照片区、上传 1–9 张照片、底部加号/发送 | 不显示假用户故事、青春结论；欢迎为引导，实际消息逐条追加 |
| 03 理解 | 顶部照片组、真实处理中提示、玻璃 Agent 气泡、绿色点缀 | 同一聊天流持续滚动，不切换为覆盖上一份结果的静态区 |
| 03 确认 | 记忆标题与可确认方向 | 卡片放消息流，显示记忆/情绪/曲风/编曲；按钮“按这个生成” |
| 固定建议 | 输入框和用户自由文字 | 删除四个预设纠正按钮，不用固定问题控制推进 |
| 旧卡 | 历史可读 | 新输入后“待更新”，新版出现后“已更新”，确认禁用 |
| 导航 | 02→03→04，创建页无底栏 | state 仅视觉，同一 draft；返回不能清空草稿 |

路径：`/create?draft=<id>` 为 02；`/create?draft=<id>&state=understanding` 为 03。原 `/create` 恢复当前浏览器最后草稿，无可恢复草稿才新建；首页创建按钮/加号显式使用 new 标志发起新草稿，完成后移除 new。`/result?draft=<id>&snapshot=<id>` 交接确认快照。query 不承载故事、照片数据或凭证。

顶部返回按已有页面导航离开，已接收内容保留；修改照片使用现有加号/管理照片入口；增删至零也不删除聊天。首次照片上传成功 commit 自动观察。发送始终处理输入，确认主要在卡片，不再随输入是否为空把发送切成确认。

消息区滚动，输入区稳定可达；消息很多时照片区可以跟随内容滚动，但不能改造成桌面侧栏布局。用户在底部阅读时新消息跟随，在历史位置时保留阅读位置并提示新消息。处理期间发送禁用但保留输入文字；每轮失败原位置显示错误/重试。

验收：02/03 的 320/375/430、较大字体、长回复、键盘、照片管理、两张卡版本、旧卡禁用、恢复返回与 03→04；对照 02/03 PNG 逐项记录保留/覆盖项。04–09 仅验输入衔接与原主链回归，06 原创建音乐调整不改版。
