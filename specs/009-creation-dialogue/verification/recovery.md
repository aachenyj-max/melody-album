# 恢复与草稿隔离

2026-10-09，生产构建 Edge 自动验收：同一真实草稿连续刷新三次，所有可见消息 id 与卡版本一致；离开首页后普通 `/create` 恢复最后草稿，照片经会话私有读取路由恢复。重新打开指定草稿同样保留已接收消息。

独立且明确标识 demo 的界面夹具：双击发送只发一次接收请求；接收成功后故意丢失 HTTP 响应，输入框识别已接收消息并清空，服务端仅一个 user。pending 轮显示重试，重试后成功追加助手，无重复 user。已有长消息时滚动到历史顶部再发送，位置保持，并显示“查看新消息”，点击才跟随到底部。

首页显式新建获得不同 id；再打开原 id 仍可读原五条消息，两个草稿不混用。GET 不调用模型，刷新不自动重跑 pending/failed；租约超过 60 秒转 interrupted，用户主动重试。

结果页按 draft/snapshot 查询参数读取，匹配前不使用上一个确认输入启动音乐；使用 useSearchParams，并按本地 Next 文档增加 Suspense。每个快照仅启动一次，切换查询参数需恢复对应音乐方向。补验结果统一记入 README.md。
