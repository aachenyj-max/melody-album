# 实施后验收指南

本轮只有规格/计划/任务，以下场景均尚未执行，不能当作通过记录。

## 前置

实施完成后应用草稿迁移与私有 bucket；通过 Supabase MCP 只读 `select 1 as connected`；建立有效匿名/auth/demo 会话。真实模型使用现有 Pi/Qwen 发布配置，key 只在服务端。新对话配置单独版本冻结；工作台 active 不自动影响用户端。`npm run dev` 启动；发布前运行 format/lint/tscheck/build。真调用与 demo/故障夹具证据分开。

## US1：真实连续聊天（SC-001/002）

分别使用毕业照和宠物照建立两段草稿。上传自动得到简短观察；每段聊五轮：补充人物→纠正事件→改变情绪→指定曲风→“你来决定”。记录 message id/顺序与回复内容，核对早先纠正和实际照片；无假用户消息、固定四个建议、固定问卷或旧回复覆盖。每轮最多一个关键问题。

## US2：最新方向交接（SC-004/008）

形成第一张卡后改“爵士、轻快一点”，旧卡待更新且禁用。新版卡出现后旧卡已更新；检查记忆、mood/style/tempo/structure/instrumentalPrompt。确认新版进入 04，对照服务端 snapshot，验证 music-session 不重新推导覆盖曲风。完成生成→05 实际播放→07 保存→08→09 刷新回读。确认前观测无音乐生成请求；重复确认不多出 snapshot。

## US3：持久恢复（SC-003/006/008）

同一段对话刷新三次，离开返回一次，关闭标签再打开一次；恢复照片、完整消息、卡和 turn。新建第二段原草稿不覆盖；两段指定链接分别恢复。pending/running 期间刷新观测，响应丢失后 GET 恢复；进程中断超过租约显示 interrupted 可重试。新访客 cookie 环境互读 draft/photo/snapshot 和 confirm 全部拒绝，不能通过 UUID 获得他人内容。

## US4：照片/失败/竞争（SC-004/005/006）

有卡后增一张、删一张、删至零：旧卡失效，变化消息只有一次，Agent 基于当前集合；零张不生成。上传失败不提交变更。模型 timeout/unavailable/invalid-result 三类故障：用户消息和历史仍在，同 turn 重试不重复 user。双击发送、重复重试、双标签修改产生明确冲突。旧请求运行时改照片，迟到结果不发布；历史已删除图不再输入模型。断网发生在消息接收前和接收后分别核对未发送/已保存状态。

## 视觉与清理（SC-007）

对照 02/03 PNG 与 [视觉覆盖](contracts/ui-navigation.md)，在 320/375/430、较大字体、长回复、卡片版本、照片管理以及移动软键盘下截取状态。旧消息阅读不被拉到底部，输入/发送可达无横向溢出。验原 02→03→04 与 04–09 主链。

隔离草稿模拟到期，先拒绝访问再移除私有对象与关系记录；删除失败再维护重试；已确认快照引用图片与已保存相册照片不误删。密钥扫描包括浏览器 JS、公共错误、持久化验收文件，凭据保留仅忽略目录。
