# 功能规格：保存音乐相册与 Supabase 数据

**Feature Branch**: `master`（当前分支；未配置建分支钩子）

**Created**: 2026-10-05

**Status**: Draft

**Input**: User description: “原型和文档里的第5阶段”——按 `progress.md` 的 SDD-05「保存音乐相册与 Supabase 数据」解释。

## User Scenarios & Testing

### User Story 1 - 保存当前音乐记忆 (Priority: P1)

用户在沉浸式播放页进入 07 号保存页，确认或修改事件标题、事件时间和一句话记忆后，把本次照片、记忆理解、当前可播放音乐和推荐歌曲保存到“我的音乐记忆”。保存成功后按原型进入 08 号列表，并能打开刚保存的相册详情。

**Why this priority**: 保存是创建流程从一次性体验变成可再次打开的音乐相册的关键动作，也是 MVP 主链路的闭环。

**Independent Test**: 使用一组已确认照片、记忆和可播放音乐进入 07 号页，填写标题与一句话记忆并保存，验证成功反馈、08 号列表的新记录和该记录的 09 号详情内容。

**Acceptance Scenarios**:

1. **Given** 07 号页收到当前创作流程的有效交接，包含 1–9 张照片、已确认记忆和一条可播放的 AI 配乐或 QQ 音乐，**When** 用户填写有效标题并点击“保存到我的音乐记忆”，**Then** 应用保存完整相册并进入 08 号列表，新相册可进入对应的 09 号详情页。
2. **Given** 用户只填写或修改事件时间、一句话记忆或标题中的部分内容，**When** 用户保存，**Then** 未修改的有效内容保持不变，保存结果显示用户最终确认的内容。
3. **Given** 当前 AI 配乐生成失败但已有可播放的 QQ 音乐推荐，**When** 用户保存，**Then** 相册保存 QQ 音乐及失败状态，不要求等待或重新生成 AI 配乐。
4. **Given** 标题为空、没有照片或当前没有可播放的成品音乐，**When** 用户尝试保存，**Then** 保存被阻止并显示具体修复提示，页面保留当前输入和返回播放入口。

### User Story 2 - 刷新后找回并浏览音乐记忆 (Priority: P1)

用户保存成功后，可以在 08 号“我的音乐记忆”列表看到相册，刷新或稍后重新打开仍能进入同一相册详情。详情页展示事件信息、照片、已保存音乐和 QQ 音乐推荐，并保留原型规定的后续入口。

**Why this priority**: 用户能否在之后找回记忆，决定保存动作是否真正提供了长期价值。

**Independent Test**: 保存一个包含多张照片和两类音乐信息的相册，刷新列表和详情页面，核对标题、日期、照片顺序、音乐来源和推荐内容仍一致；再检查无记录时的空状态。

**Acceptance Scenarios**:

1. **Given** 用户已有保存成功的相册，**When** 用户打开或刷新 08 号列表，**Then** 列表按最近创建时间显示该相册的封面、标题、日期和可用音乐摘要。
2. **Given** 用户在 08 号列表点击某个相册，**When** 详情加载完成，**Then** 09 号页展示该相册的标题、事件时间、记忆短句、照片组、当前音乐和推荐歌曲，且照片顺序与保存时一致。
3. **Given** 当前用户没有已保存相册，**When** 用户打开 08 号列表，**Then** 页面显示可理解的空状态和创建入口，不显示示例相册冒充用户数据。
4. **Given** 详情中的保存音乐或推荐歌曲暂时不可播放，**When** 用户查看 09 号页，**Then** 元信息仍可见并显示不可播放状态，页面提供返回列表或重新生成音乐的入口，不报告虚假的播放成功。

### User Story 3 - 在保存失败时安全恢复并保持数据边界 (Priority: P1)

用户遇到网络、会话、照片存储或保存服务失败时，能看到明确的失败原因摘要，保留当前结果并重试；不同用户只能看到自己的音乐记忆。重复点击保存不会产生重复相册。

**Why this priority**: 保存涉及照片和多个内容部分，失败或越权会直接损害用户对记忆可靠性和隐私的信任。

**Independent Test**: 分别模拟保存失败、照片上传失败、会话回退和重复点击，验证原页面可恢复、重试可用、不会出现半成功提示或重复记录；再用两个用户标识验证列表和详情互相隔离。

**Acceptance Scenarios**:

1. **Given** 保存请求或照片存储失败，**When** 用户查看结果，**Then** 07 号页保留标题、时间、短句和当前音乐，显示可重试的失败状态，不跳转到不存在的详情页。
2. **Given** 用户点击保存后网络变慢，**When** 用户再次点击或刷新，**Then** 应用只产生一个可识别的保存结果；重试不会创建重复相册，也不会覆盖已有成功记录。
3. **Given** 项目启用了匿名会话，**When** 用户保存并再次访问列表，**Then** 数据归属于该匿名用户；未启用匿名会话时使用服务端固定演示用户标识，仍按该标识隔离。
4. **Given** 两个不同用户标识访问列表或详情，**When** 其中一方请求另一方的相册，**Then** 请求被拒绝或返回不存在状态，不泄露标题、照片、音频地址或推荐信息。

### Edge Cases

- 07 号页被直接打开或刷新且没有 SDD-04 的有效交接：显示空状态和返回生成结果入口，不使用历史 mock 数据填充当前保存表单。
- 选择的照片数量为 0 或超过 9 张：阻止保存并提示回到创建流程修正照片组。
- 标题只含空格、超过允许长度或包含无法保存的内容：保留用户输入并提示具体格式要求。
- 事件时间为空、格式无效或处于未来：允许按产品约定保存为空，或提示修正；不得把无效时间显示为已确认日期。
- 一句话记忆为空：允许保存并在详情中隐藏该字段；非空内容应按用户最终确认值显示。
- AI 配乐只有元信息没有可播放音频：不能作为保存时的当前成品；若 QQ 音乐有可播放结果，应允许保存 QQ 音乐。
- AI 和 QQ 音乐都不可播放：保存按钮不可用，并提供返回结果页重试入口。
- 照片上传部分成功、部分失败或短时访问地址过期：相册不得报告成功；用户可重试，已创建的孤立数据不可出现在用户列表中。
- 保存成功后用户快速返回或重复打开详情：详情仍指向同一相册，不创建新记录。
- 读取列表或详情超时：显示加载失败和重试，不把空列表误报为“没有记忆”。
- 用户退出会话或会话标识变化：旧用户数据不应出现在新用户列表中。
- 窄屏、较大系统字体和无障碍模式下，07–09 号页面的表单、卡片、照片和主要按钮仍可读可操作，无明显横向溢出。

## Requirements

### Functional Requirements

- **FR-001**: 保存流程 MUST 只接受 SDD-04 交接的当前创作结果；缺少已确认记忆、照片组或当前会话时 MUST 显示空状态，不得使用历史演示相册代替。
- **FR-002**: 07 号保存页 MUST 允许用户编辑事件标题、事件时间和一句话记忆，并在提交前显示当前照片组、音乐选择和推荐摘要。
- **FR-003**: 标题去除首尾空白后 MUST 非空且不超过 80 个字符；一句话记忆去除首尾空白后最多 300 个字符；事件时间为空时 MUST 按空值保存，格式无效时 MUST 阻止提交并说明原因。
- **FR-004**: 保存 MUST 要求照片数量为 1–9 张，并要求当前音乐选择至少包含一条实际可播放的 AI 配乐或 QQ 音乐；通用等待音乐和只有元信息的歌曲 MUST 不能作为保存成品。
- **FR-005**: 保存成功 MUST 记录相册标题、事件时间、用户短句、照片顺序与元数据、当前音乐版本、QQ 音乐推荐、来源状态和创建时间，并保持这些内容与同一次记忆理解的关联。
- **FR-006**: 照片原文件 MUST 存放在私有照片存储中；读取详情时 MUST 使用受访问控制的短时地址或等效保护方式，不得把用户照片默认暴露为公开资源。
- **FR-007**: 保存过程 MUST 记录可追踪的生成和保存状态，包括 AI 配乐成功、失败或未完成，以及 QQ 音乐推荐是否可用；AI 失败不得清除可保存的 QQ 音乐结果。
- **FR-008**: 应用 MUST 优先使用当前用户的匿名会话；匿名会话不可用时 MUST 使用服务端固定演示用户标识回退，且该回退不得把用户数据写入浏览器可见的共享身份。
- **FR-009**: 数据读取 MUST 按用户标识隔离；列表、详情、照片短时地址、音乐信息和失败记录均不得被其他用户访问或通过可猜测标识枚举。
- **FR-010**: 保存成功后 MUST 按 HTML 热点进入 08 号列表并能打开对应的 09 号详情页；“稍后再说” MUST 返回 05 号播放页并保留当前创作结果，但不得宣称已经保存。
- **FR-011**: 08 号列表 MUST 读取当前用户已保存相册，按创建时间倒序展示封面、标题、日期和音乐摘要；无记录时 MUST 展示空状态与创建入口。
- **FR-012**: 09 号详情 MUST 展示保存时的标题、事件信息、记忆短句、照片组、当前音乐和推荐歌曲，并提供原型规定的返回列表与重新生成音乐入口。
- **FR-013**: 保存失败、照片存储失败、读取失败和会话失败 MUST 显示可理解的错误状态；失败时 MUST 保留可重试输入，不得导航到伪造的成功详情。
- **FR-014**: 重复点击、网络重试或刷新恢复 MUST 具备幂等行为；同一次保存尝试最多产生一个相册，重试不得覆盖已经成功且可读取的相册。
- **FR-015**: 当多个内容部分无法同时完成时，系统 MUST 只报告完整可读取的保存成功；未完成的部分 MUST 进入失败或可重试状态，并清理或隔离用户不可见的残留记录。
- **FR-016**: 07、08、09 号页面 MUST 按 `音乐相册-ui还原.html` 与 `designs/ui/07`–`09` PNG 保持页面顺序、主要层级、按钮文案、照片位置和主要跳转：07 保存成功进入 08，08 的相册卡片进入 09，09 的“生成音乐”进入 04。
- **FR-017**: 当前项目使用的 Supabase 数据与私有照片存储 MUST 遵守浏览器/服务端密钥边界；保存和读取行为不得向用户端暴露服务端密钥或其他用户的访问凭证。

### Key Entities

- **音乐相册**：一次保存成功的记忆集合，包含标题、事件时间、用户短句、创建时间、所属用户和当前可用音乐。
- **相册照片**：相册中的有序照片记录，包含显示顺序、原始文件元数据、受保护的存储位置和读取状态。
- **音乐版本**：与相册关联的 AI 配乐或用户选中的 QQ 音乐，包含来源、标题、可播放状态、音频位置和生成版本。
- **推荐歌曲**：与本次记忆关联的 QQ 音乐候选，包含歌曲识别信息、推荐理由、来源和可播放状态；不可播放时仍可保留元信息。
- **生成与保存运行记录**：记录 AI 配乐、推荐和保存各轮的状态、失败类别、重试关系和时间，用于恢复与排查，不改变用户可见的最终内容。
- **用户会话标识**：匿名会话或固定演示用户标识，用于隔离列表、详情、照片和音乐资源。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在网络正常且包含 9 张照片的演示场景中，用户从点击保存到看到包含新相册的 08 号列表的时间不超过 30 秒，且能打开 09 号详情页；失败时在 5 秒内看到可理解的失败反馈。
- **SC-002**: 10 次保存成功演示中，10 次刷新 08 号列表并重新打开详情后都能看到相同的标题、照片顺序、日期和已保存音乐信息。
- **SC-003**: 在 AI 配乐失败但 QQ 音乐可播放的 10 次演示中，10 次都能保存并在详情中看到 QQ 音乐；不存在因 AI 失败导致的保存阻断。
- **SC-004**: 对同一保存动作连续点击或重试 10 次，最终最多出现 1 条相册记录，且已成功记录的内容不会被失败重试覆盖。
- **SC-005**: 使用两个不同用户标识各保存 3 个相册时，双方列表和详情均只显示自己的 3 个相册，交叉访问不返回对方的标题、照片或音乐信息。
- **SC-006**: 在至少 3 个常见移动视口宽度下，07、08、09 号界面的布局、层级、配色、字体、图片位置、按钮文案和主要跳转符合对应 PNG 与 HTML，且无明显横向溢出。
- **SC-007**: 保存服务不可用、照片存储失败、详情读取失败和无数据四类场景均显示明确状态；每类场景都有可执行的重试、返回或创建下一步，且没有伪造成功结果。
- **SC-008**: 至少 90% 的首次使用者能在 2 分钟内完成“确认保存 → 打开详情 → 从列表再次打开”的核心任务，并能说出相册已保存的位置。

## Assumptions

- “第5阶段”指规划文档与 `progress.md` 的 SDD-05，承接 SDD-04 的 07 号保存交接，并补齐 SDD-01 的 08、09 号真实读取。
- 项目已选 Supabase 作为数据库和私有照片存储载体；具体表、字段、访问策略和迁移步骤在后续 plan/tasks 中落实，用户体验以本规格的保存、读取、隔离和失败行为为准。
- 按规划文档已确认的 Demo 策略，优先使用 Supabase 匿名会话；未开启匿名登录时由服务端使用固定演示用户标识回退，不引入登录页面。
- 照片存储使用私有 bucket，数据库只保存受保护的存储路径和必要元数据；详情读取时生成短时访问地址，地址失效后可重新获取。
- SDD-02、SDD-03、SDD-04 已交付的记忆、照片、音乐结果和来源状态是保存输入；本阶段不重新理解照片、不重新生成音乐。
- 生成失败记录可以随相册保存，前提是至少有一条可播放的音乐结果；等待音乐不能被误保存为个性化成品。
- 保存后的标题、事件时间、短句和照片组在本阶段只读；编辑已保存相册、删除相册、真实分享和跨用户协作属于后续范围。

## Out of Scope

- 登录、注册、密码找回和完整账户管理页面。
- 新的 Agent 记忆理解、音乐生成、QQ 音乐检索或沉浸式播放实现。
- 已保存相册的编辑、删除、版本比较、多人协作和跨设备共享链接。
- 歌词、人声、完整歌曲、自动事件归档、收藏和真实分享能力。
- 内部 Agent 工作台及其运行记录对比。
