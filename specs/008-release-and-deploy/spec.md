## User Scenarios & Testing

### User Story 1 - 在目标环境完成音乐相册主链路 (Priority: P1)

演示人员用真实照片从首页创建音乐相册，检查记忆理解、音乐结果、播放、调整和保存，并在刷新后从“我的音乐记忆”重新打开相册。每个阶段如实显示真实、演示或 mock 来源，使观众能够区分已接通能力与演示能力。

**Why this priority**: 可重复完成且能在刷新后找回的主链路，是本次 MVP 可交付的直接证据。

**Independent Test**: 在目标环境使用一组 1–9 张真实照片，按 01→02→03→04→05→06→05→07→08→09 的原型流程操作，保存后刷新并从列表重新打开同一相册；记录各结果来源和保存内容。

**Acceptance Scenarios**:

1. **Given** 目标环境已具备本次演示所需的有效配置和一组真实照片，**When** 演示人员完成上传、理解与修正、确认、生成或选择音乐、播放、调整和保存，**Then** 每一步显示其实际状态，保存后按 HTML 热点进入 08 号列表并能打开对应的 09 号详情，刷新后仍能从记忆列表打开相同标题、照片、时间、记忆短句及已保存音乐。
2. **Given** AI 配乐仍在生成，**When** 演示人员进入结果与播放流程，**Then** 等待音乐与个性化配乐清晰区分；只有已验证可播放的 AI 配乐或 QQ 演示推荐可以作为保存成品，等待音乐不能被保存为成品。
3. **Given** AI 配乐生成失败，但本次存在可播放的 QQ 演示推荐，**When** 演示人员选择该推荐继续播放并保存，**Then** 保存成功，详情保留 AI 失败状态及 QQ 来源，不把推荐标为 AI 成品或真实 QQ 曲库结果。
4. **Given** Agent 运行在明确标记的演示模式，或 QQ 推荐仍来自本地 mock，**When** 用户查看理解、结果和保存记录，**Then** 来源标识持续可见；验收记录分别注明真实服务已验证的范围和仅以演示模式验证的范围。

### User Story 2 - 在九个原型画面中顺畅完成操作 (Priority: P1)

用户在常见手机尺寸上浏览 01–09 号界面，看到与设计稿对应的布局、照片、标题、按钮和页面层级，并能按原型热点完成主要跳转。加载、空状态和失败状态给出明确的继续办法。

**Why this priority**: 产品演示依赖原型一致性；页面可到达但画面错位、跳转错误或失败后无路可走，都会使主链路不可用。

**Independent Test**: 逐页对照 `designs/ui/01`–`09` PNG 与 `音乐相册-ui还原.html`，在 320、375、430 像素宽度及较大字体下检查视觉和主要热点；分别触发加载、空数据、失败、返回及重试。

**Acceptance Scenarios**:

1. **Given** 用户打开任一编号的用户端界面，**When** 对照同编号 PNG 和 HTML，**Then** 布局、层级、配色、字体、图片位置、按钮文案及主要跳转与原型一致；动态数据可以不同，但画面结构和编号顺序保持不变。
2. **Given** 用户在任一阶段遇到等待、空数据、网络失败或无可播放音源，**When** 用户查看当前页面，**Then** 页面说明实际状态并提供可执行的返回、重试或重新创建动作；未完成的生成、保存或读取不显示成功结果。
3. **Given** 用户在创建、结果、播放、调整、保存或历史详情间返回，**When** 返回当前流程，**Then** 已确认的本次输入与有效结果按既有阶段规则保留，失败候选不覆盖旧的可用结果，离开播放界面后声音停止。
4. **Given** 05 号 PNG 的按钮文案与 HTML 保存热点命名不一致，**When** 验收 05→07，**Then** 记录这一既有文案差异，并按已确认的页面文案、理解查看方式和保存跳转规则判定，不把进入 07 误判为保存成功。

### User Story 3 - 安全发布并能够恢复 (Priority: P1)

发布负责人在上线前核对质量检查、配置和隐私边界，发布后记录地址与验证结果。如果线上版本出现阻断主链路的问题，负责人可以依据已记录的恢复步骤回到上一个可用版本。

**Why this priority**: 只有可访问、可验证、无凭证泄露且能够恢复的版本，才算可部署交付。

**Independent Test**: 对拟发布版本执行项目要求的四项质量检查；在目标环境核对公开页面与内部工作台的访问边界、浏览器可见配置及错误输出；发布并完成主链路冒烟验收，演练或核实恢复步骤。

**Acceptance Scenarios**:

1. **Given** 一个拟发布版本，**When** 发布负责人运行格式化、代码质量、类型与生产构建检查，**Then** 四项均通过，失败项在发布前修复并重新验证。
2. **Given** 目标环境已配置公开连接信息和服务端凭证，**When** 检查用户端页面、网络响应、可下载资源和错误信息，**Then** 服务端凭证、未授权相册的照片访问地址与内部工作台数据均不可由未授权访客获取；内部工作台不出现在用户导航，未配置内部口令时不可访问。
3. **Given** 新版本已发布，**When** 发布负责人按保存后的验收步骤访问部署地址，**Then** 可完成一次上传到刷新查看的主链路，且记录版本、地址、时间、验证结果、已知限制和恢复路径。
4. **Given** 新版本上线后出现阻断上传、播放或保存的问题，**When** 负责人执行已记录的恢复步骤，**Then** 能恢复到最近一次通过主链路验收的可用版本，并记录恢复结果。

### Edge Cases

- 新用户没有历史相册、历史读取失败或保存后记录未立即出现时，分别展示真实空状态、可重试的错误或同步等待状态；不得用演示相册冒充刚保存的记录。
- 照片选择不足、超过 9 张、文件损坏、上传中断或保存照片失败时，指出原因，并保留可恢复的当前输入与操作入口。
- 记忆理解、音乐生成、音乐调整或推荐任一分支失败或超时，显示对应分支状态；独立的可用结果不得被清除或伪装为另一来源。
- 自动播放受浏览器限制、音频地址不可播或播放中断时，提供手动开始或重新选择入口；不能把仅有歌曲元信息或等待音乐当作可保存的成品。
- 保存请求重复提交、服务暂时不可用或详情读取失败时，不产生被误认的重复成功记录；用户可核对结果并安全重试。
- 直接打开或刷新需当前创作会话的中间页面时，没有交接数据应显示明确空状态及返回入口，不填入历史 mock 伪造本次创作。
- 目标环境缺少外部服务凭证时，只能进入已有且明确标记的演示模式；真实服务调用失败必须显示失败，不得静默改写来源。
- 内部工作台发生错误或未配置口令时，用户端主流程不受影响；内部记录不出现在用户端页面或公开响应中。
- 窄屏、较大字体、减弱动态效果及键盘操作下，九个用户端画面的主要内容和操作仍可读、可达，无明显横向溢出。
- 发布完成但线上验证失败时，版本不得被标记为 SDD-07 完成；记录失败原因、恢复结果和待重新验证项。
- 若前置阶段文档、实现与 HTML 热点对 07 保存落点产生分歧，上线验收以项目规定的 07→08→09 流程为准，并在发布前统一记录。

## Requirements

### Functional Requirements

- **FR-001**: 目标环境 MUST 支持用户以 1–9 张真实照片完成“上传 → 记忆理解与修正 → 确认 → AI 配乐状态及 QQ 推荐 → 播放与调整 → 保存 → 刷新后查看详情”的完整流程。
- **FR-002**: 上线验收 MUST 分别覆盖正常生成、慢响应、AI 配乐失败但有可播推荐、保存失败及历史读取失败；每类状态 MUST 有与真实结果一致的反馈和可执行的继续动作。
- **FR-003**: 系统 MUST 在整个用户流程和保存结果中如实区分真实服务、Agent 演示适配器、QQ mock、通用等待音乐与最终可播放音乐；不得将一种来源或未完成状态宣称为另一种已完成结果。
- **FR-004**: 仅有已验证可播放的本次 AI 配乐或 QQ 演示推荐时，用户 MUST 能进入保存流程；仅有等待音乐、元信息或失败候选时 MUST 阻止保存成品，并说明原因。
- **FR-005**: 01–09 号用户端界面 MUST 逐页符合对应 PNG 的布局、层级、配色、字体、图片位置和按钮文案，并符合 HTML 中对应的主要热点目标，包括 07 保存后进入 08、08 相册卡片进入 09；动态内容 MAY 替换示例数据，但不得改变界面结构、编号顺序和底部导航出现位置。
- **FR-006**: 页面加载、空状态、失败、返回和重试 MUST 覆盖创建、理解、结果、播放、调整、保存、列表和详情的主要操作；操作失败 MUST 保留可恢复的有效输入或结果，不显示虚假成功。
- **FR-007**: 保存成功后 MUST 可刷新并从历史列表重新打开同一相册，核对标题、事件时间、照片、记忆短句、当前音乐与来源状态；保存失败 MUST 保留当前内容以便重试。
- **FR-008**: 发布前 MUST 通过项目既定的格式、代码质量、类型和生产构建四项检查，并留存检查结果；任一检查失败时不得宣告发布验收通过。
- **FR-009**: 目标环境 MUST 仅向浏览器提供允许公开的连接配置；服务端凭证、内部访问口令及未授权相册的照片访问地址 MUST 不出现在公开页面、可下载资源、未授权网络响应或错误信息中。
- **FR-010**: 内部 Agent 工作台 MUST 保持独立于 01–09 号用户端导航；未获内部访问资格的访客 MUST 不能查看运行记录或发起测试。工作台异常 MUST 不阻断用户端主流程。
- **FR-011**: 发布交付 MUST 记录部署地址、发布版本、线上验证步骤与结果、各集成的真实或演示验收范围、已知限制及恢复到上一个可用版本的步骤。
- **FR-012**: SDD-07 完成状态 MUST 仅在目标环境主链路、九页视觉与跳转、失败兜底、凭证边界和四项质量检查全部通过后更新；失败或尚未验证的项目 MUST 明确记录为限制或阻塞。

### Key Entities

- **发布版本**：一次待验收或已上线的交付，包含版本标识、部署地址、发布时间、验收状态和对应的上一个可用版本。
- **验收记录**：按场景保存操作步骤、输入范围、实际结果、来源模式、检查时间、通过或失败状态及证据位置。
- **相册**：用户完成一次创作后保存并可重新打开的记忆集合，包含标题、事件时间、照片、记忆短句、音乐及来源状态。
- **恢复记录**：出现阻断问题时的触发原因、恢复目标版本、执行步骤和恢复验证结果。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在目标环境使用至少 1 组真实照片完成 1 次完整主链路，保存后刷新并从列表重新打开，标题、事件时间、照片数量、记忆短句、所选音乐与来源 6 项均与保存前一致。
- **SC-002**: 正常生成、慢响应、AI 失败但推荐可播、保存失败、历史读取失败 5 类验收场景均能显示真实状态；每类都至少提供 1 个可执行的继续、重试或返回动作，且 0 次显示伪造成功。
- **SC-003**: 01–09 共 9 个界面在 320、375、430 像素宽度下完成逐页核对；27 个“界面 × 宽度”组合均无明显横向溢出，主要操作可达，主要热点目标与 HTML 一致。
- **SC-004**: 对九个界面逐项记录布局、层级、配色、字体、图片位置和按钮文案的核对结果；所有影响主流程辨识或操作的差异在上线前解决，保留的非阻断差异有明确记录。
- **SC-005**: 拟发布版本的格式、代码质量、类型和生产构建 4 项检查全部通过；任一失败时不进入“已验收上线”状态。
- **SC-006**: 在未授权访客可访问的页面、资源、响应及错误信息检查中，发现的服务端密钥、内部口令、其他用户照片访问地址和私有测试记录泄露数量为 0；无口令或未验证访问工作台的尝试均被阻止。
- **SC-007**: 线上验收记录包含 1 个可访问的部署地址、1 个发布版本、至少 1 次完整主链路结果、各外部集成的来源状态、已知限制及 1 份经核实的恢复步骤。
- **SC-008**: 当演示 AI 配乐失败但 QQ 演示推荐可播时，至少 1 次完整完成选择、播放、保存和刷新查看，详情保留真实失败状态及推荐来源。

## Assumptions

- “第 7 阶段”指 `docs/音乐相册-MVP分阶段开发部署规划.md` 和 `progress.md` 中的 SDD-07「MVP 验收、硬化与上线」；原型的 07 号“保存音乐相册”画面属于 SDD-05，在本阶段只进行复核。
- SDD-05 的保存、私有照片和历史读取已完成本地验收，07 保存进入 08、再由列表进入 09；SDD-06 的内部工作台边界需在发布前完成并可验收。本阶段修复验收发现的阻断问题，不新增产品功能或重做前置阶段业务。
- 本阶段以项目既定的目标托管环境进行发布，最终地址和恢复方式在实施时记录；规格不预设具体发布账户或域名。
- Agent 真实入口和凭证如仍不可用，允许沿用 SDD-02/06 已定义且明确标记的演示模式完成演示验收，但验收记录必须注明未验证真实 Agent；QQ 推荐沿用已确认的 mock 边界。真实音乐生成仅在配置有效且调用成功时记为真实服务通过。
- 已保存照片和相册遵守前置阶段确定的私有访问、用户隔离与刷新可恢复规则；本阶段检查这些规则，不重新设计登录或存储方案。
- 05 号画面的“查看 AI 理解”文案与 HTML 同位置保存热点之间的已知差异，按 SDD-04/05 确认的解释查看与保存规则验收并记录，不在发布阶段擅自修改原型文案。
- 先前的 SDD-05 保存落点冲突已在 SDD-05 实施和文档中统一为 07→08→09；本阶段复核线上行为，不重复实施保存流程。
- 页面视觉以九张 PNG 为准，主要跳转以 HTML 热点为准；内部工作台不属于九张用户端画面。

## Out of Scope

- 歌词生成、完整原创歌曲、真实分享、自动事件归档、多人共创和年度记忆。
- 将 QQ mock 宣称为真实 QQ 曲库接入，或将 Agent 演示结果宣称为真实 Pi Agent 结果。
- 新建用户登录、公开内部工作台、在线编辑 Agent 配置或增加新的用户端页面。
- 在本阶段重新定义 01–09 的页面结构、导航顺序或 SDD-02 至 SDD-06 的核心业务契约。
