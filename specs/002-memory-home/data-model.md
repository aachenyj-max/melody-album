# 数据模型：历史音乐记忆演示

本阶段数据在仓库内静态定义，用于首页、列表和详情的一致展示。字段含义与未来持久化数据对齐，但此处不设计数据库结构。

## 音乐记忆（DemoMemoryAlbum）

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `id` | 稳定的详情地址标识 | 非空、唯一；刷新不变 |
| `title` | 记忆标题 | 非空，卡片与详情一致 |
| `coverImage` | 封面图片地址或图形封面值 | 有值；资源不可用时呈现明确占位 |
| `photos` | 照片预览或描述集合 | 可为空；详情显示缺省状态 |
| `tracks` | 关联歌曲/配乐集合 | 可为空；详情显示“暂无音乐” |
| `createdAt` | 相册创建日期 | 可展示为中文日期；列表按其倒序 |
| `eventDate` | 事件日期 | 可与创建日期不同；不用于默认排序 |
| `caption` | 记忆的一句话描述 | 可为空；为空时不显示引述区域 |
| `subtitle` | 列表卡片的简述 | 可为空；为空时显示缺省文案 |
| `photoCount` | 相册照片总数 | 非负整数；可大于本地预览数组长度 |
| `trackCount` | 已保存音乐数 | 非负整数；与推荐歌曲条数分别计算 |
| `category` | 演示分类标签 | 本阶段仅展示，不启用筛选 |

**关系**：一条音乐记忆拥有零到多项照片预览、零到多条歌曲信息。首页摘要、列表卡片和详情都读取同一条记录，不另存多份文案。

## 照片预览

当前代码中 `photos` 是本地照片预览地址的子集，`photoCount` 表示原型所示的相册总照片数，二者可以不同。没有可用预览时显示图形占位；本阶段不实现完整照片浏览。

## 歌曲信息（DemoTrack）

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `id` | 稳定标识 | 相册内唯一 |
| `title` | 歌曲或配乐标题 | 非空 |
| `artist` | 歌手或“AI 无歌词配乐”说明 | 非空 |
| `kind` | AI 配乐或 QQ 音乐推荐 | 仅用于标识来源，不触发播放 |
| `status` | 演示可展示/占位状态 | 不代表实际音源可播放 |

## 展示状态

| 状态 | 触发条件 | 用户可见结果 |
| --- | --- | --- |
| 非空列表 | 演示集合至少 1 条 | 按创建日期倒序显示卡片 |
| 空列表 | 演示集合为空 | 空状态文案及创建入口 |
| 已知详情 | ID 匹配记录 | 标题、照片、歌曲、日期与列表一致 |
| 未知详情 | ID 不匹配记录 | 未找到提示和返回列表入口 |
| 字段缺失 | 照片、歌曲或日期不可用 | 明确的缺省文案，不留破损空白 |

## 校验

- 演示集合至少准备 2 条不同记忆，标题、封面、歌曲和日期保持固定。
- ID 不重复；详情链接只能使用集合中的 ID。
- 日期展示与排序口径固定；不在渲染时调用随机值或当前时间生成内容。
- 现有 `getDemoMemoryAlbum(id)` 可以继续作为按 ID 读取入口。
