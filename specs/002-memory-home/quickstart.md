# 快速验收：音乐相册首页与历史记忆

## 前置条件

- 已安装仓库依赖；SDD-00 的 App Shell 和创建初始状态可访问。
- 本阶段至少准备 2 条固定的本地演示记忆。无需真实 Agent、音乐接口或数据库连接。
- 行为预期见 [UI 导航契约](contracts/ui-navigation.md)，字段口径见 [数据模型](data-model.md)。

## 启动

在仓库根目录运行：

```powershell
npm run dev
```

打开本地服务显示的地址。

## 手工验收

1. 打开首页，确认 10 秒内能识别“上传照片，生成一段记忆”主入口；点击后在 3 次点击内到达创建初始状态。
2. 返回首页，查看至少一条最近记忆；点击“查看全部”进入“我的音乐记忆”。
3. 确认列表至少 2 条、按创建日期倒序、每条显示封面或照片预览、标题、歌曲摘要和日期。点击一条进入对应详情，核对标题、照片、歌曲和日期与列表一致。
4. 连续刷新首页和列表 5 次，确认同一组演示内容仍出现且信息不随机变化。直接打开一个已知详情地址，再打开未知 ID，核对返回入口和未找到反馈。
5. 检查空列表、缺少照片/歌曲/日期时的展示；可临时调整本地演示集合完成此项，验收后恢复固定数据。
6. 点击探索/推荐、个人中心和分享占位，确认有明确反馈或安全停留，且没有新链接、业务写入或虚假的成功状态。
7. 在 320、375、430 CSS 像素宽度下检查首页、列表、详情，确认无明显横向滚动，创建、列表和返回入口可操作。

## 静态检查

```powershell
npm run tscheck
npm run lint
```

若需要确认生产编译，再运行 `npm run build`。提交阶段结果时按 `progress.md` 记录完成项、验证结果、限制与下一阶段，并在同一提交中更新进度。
