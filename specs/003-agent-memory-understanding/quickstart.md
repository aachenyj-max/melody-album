## 正常流程

1. 打开 `/`，进入 `/create`。选择 1 张照片，确认出现预览与“1/9”或等价计数；继续添加到 9 张，确认顺序、数量和删除后计数准确。
2. 不填故事提交 1 张照片；再用 1–9 张照片和故事提交一次。两种方式都应进入处理中状态，且重复点击不产生第二份结果。
3. 查看理解卡：事件标题、人物、事件、氛围、时间线五项可见；缺失项显示“未识别”。若标题存在且事件或氛围至少一项可用，可继续确认。
4. 输入“更快乐一点，但保留一点不舍”并提交。修正处理中旧结果仍可识别，成功后当前版本递增、受影响内容更新；演示来源明确标记。
5. 点击一键确认，进入 `/result`。结果页接到当前确认版本，并明确说明音乐生成/推荐属于下一阶段。直接新开 `/result` 或刷新该页时仅显示演示占位，不宣称已经处理用户照片。

## 输入与失败路径

| 操作 | 预期结果 |
| --- | --- |
| 未选照片继续 | 阻止提交，提示需 1–9 张 |
| 加到第 10 张 | 阻止超出上限，并说明当前已选数量 |
| 选择不支持格式、单张 >10 MiB 或总计 >50 MiB | 明确指出问题，已选有效照片仍可操作 |
| 9 张源图准备分析图 | 逐张处理并显示等待状态；请求体 ≤3.5 MiB，原图不直接送往服务端 |
| 图片无法压缩到请求预算内 | 明确提示移除或更换照片，不发出超限请求 |
| 选择重复文件 | 每次都作为独立照片计数并显示独立预览 |
| 预览读取失败 | 该照片可移除或重选，不进入理解请求 |
| 提交空白或超过 300 字的修正 | 保留当前有效结果并提示输入规则 |
| 返回缺少人物/时间线的部分结果 | 标为“未识别”；满足最低条件时仍可确认 |
| 返回无标题，或事件与氛围都缺失 | 不开放确认；保留照片和故事以供重试或补充 |
| 理解/修正超时、网络失败或真实 Agent 不可用 | 显示可理解错误，保留照片、故事及上一有效结果，提供重试或返回 |

本地开发可按 [理解契约](contracts/memory-understanding.md) 的 `X-Demo-Scenario` 请求头分别触发部分结果、不可用结果、超时、不可用和无法理解修正；只在演示适配器与开发环境生效，不作为用户端入口。

## 草稿清除与直接访问

1. 选择照片、填写故事或完成一次修正，但不要确认；刷新 `/create`。页面必须回到初始状态，照片、故事和修正内容不再显示。
2. 再次创建未确认草稿，离开到首页或记忆页，再返回 `/create`。页面仍应从初始状态开始。
3. 直接打开或刷新 `/create?state=understanding`。没有有效草稿时展示上传初始状态，不显示原型中的毕业示例为用户真实结果。
4. 检查页面 URL、浏览器持久存储与业务数据：不得包含照片内容、故事或未确认结果。
5. 在浏览器网络面板核对理解与修正请求大小低于 3.5 MiB；源图不作为请求文件发送。若部署在目标托管环境，确认多张照片不会触发 `FUNCTION_PAYLOAD_TOO_LARGE`。

## 移动宽度与原型

在至少 3 个常见移动宽度（如 320、375、430 CSS 像素）下检查上传区、预览、故事输入、理解卡、修正输入、一键确认、错误与返回入口。无明显横向滚动，主要操作可见可点。对照 `音乐相册-ui还原.html` 的 `screens` 顺序、02→03→04 热点，以及 `designs/ui/02-创建音乐相册-上传照片.png` 和 `designs/ui/03-创建音乐相册-Agent记忆理解.png`，逐项核对布局、层级、配色、字体、图片位置、按钮文案与主要跳转；动态内容可替换示例，界面结构不得变动。静态示例文案不得冒充本次照片的真实理解结果。
