## User Scenarios & Testing

### User Story 1 - 上传照片并开始创建记忆 (Priority: P1)

用户可以从音乐相册创建入口选择 1–9 张照片，看到照片预览，并在提交前删除或重新选择照片。用户也可以补充一段可选故事，帮助系统理解这段经历；只上传照片时也能继续。

**Why this priority**: 照片是音乐相册的核心输入。输入流程必须先稳定，后续记忆理解和音乐生成才有可靠的起点。

**Independent Test**: 在不连接真实 Agent 的情况下，选择 1 张、9 张和带故事的照片，确认每种输入都能进入记忆理解状态；删除照片或重新选择后，预览与数量保持一致。

**Acceptance Scenarios**:

1. **Given** 用户位于创建音乐相册的初始状态，**When** 用户选择 1–9 张有效照片，**Then** 页面展示每张照片的预览、当前数量和继续操作。
2. **Given** 用户已经选择照片，**When** 用户删除其中一张或重新选择照片，**Then** 页面立即移除或替换对应预览，并更新数量，不影响其他已选照片。
3. **Given** 用户只选择照片而未填写故事，**When** 用户点击继续，**Then** 应用进入记忆理解状态，不要求故事输入。
4. **Given** 用户填写可选故事并选择照片，**When** 用户点击继续，**Then** 故事与照片一起进入记忆理解流程，并在后续结果中可被识别。
5. **Given** 用户尚未确认记忆理解，**When** 用户刷新页面或离开创建页后返回，**Then** 页面回到创建初始状态，已选照片、故事与修正内容不再显示。

### User Story 2 - 查看 Agent 的记忆理解结果 (Priority: P1)

用户提交照片后，可以看到 Agent 对这段经历的结构化理解，包括事件标题、人物、事件、氛围和时间线，并知道当前正在理解、理解成功或理解失败的状态。

**Why this priority**: 结构化理解是照片到音乐表达之间的产品核心。用户需要先确认系统是否理解了自己的经历，再继续生成音乐。

**Independent Test**: 使用固定演示结果提交一组照片，验证加载、成功和失败三种状态均有清晰内容；成功状态至少展示标题、人物、事件、氛围和时间线五类信息。

**Acceptance Scenarios**:

1. **Given** 用户提交了合法照片，**When** Agent 正在处理，**Then** 页面展示明确的处理中状态，并保留取消、返回或重试入口中的至少一个安全操作。
2. **Given** Agent 成功返回理解结果，**When** 用户查看结果，**Then** 页面展示事件标题、人物、事件、氛围和时间线，并提供一键确认与修改入口。
3. **Given** Agent 返回失败或结果不可用，**When** 用户查看失败状态，**Then** 页面说明失败原因的可理解摘要，并提供重试、重新选择照片或返回入口；页面不显示伪造的成功结果。
4. **Given** 用户刷新或重新进入创建页，**When** 页面重新加载，**Then** 页面展示明确的创建初始状态，不出现空白页；用户再次提交照片后仍能得到稳定的演示理解结果。
5. **Given** 理解结果已有事件标题，且事件或氛围至少有一项，但缺少人物或时间线等部分信息，**When** 用户查看结果，**Then** 缺失项显示“未识别”，用户仍可确认当前结果并继续。

### User Story 3 - 修正并确认记忆理解 (Priority: P1)

用户可以用自然语言补充或修正 Agent 的理解，例如调整事件标题、氛围或表达重点；确认后，系统将最终理解结果交给下一阶段的音乐编排流程。

**Why this priority**: 用户对记忆的主观感受不能只靠照片推断。低成本修正和明确确认能提升情绪命中率，并为音乐生成提供用户认可的输入。

**Independent Test**: 在成功理解结果上提交“更快乐一点，但保留一点不舍”等修正，确认修正后结果可辨识、状态可追踪，并能点击确认进入音乐结果页或下一阶段占位状态。

**Acceptance Scenarios**:

1. **Given** 页面展示成功的理解结果，**When** 用户提交自然语言修正，**Then** 页面显示修正处理中状态，完成后更新受影响的标题、氛围或描述，并保留未受影响的信息。
2. **Given** 用户提交空白或无法识别的修正内容，**When** 系统处理输入，**Then** 页面提示用户补充具体内容，不覆盖当前有效理解结果。
3. **Given** 用户对结果满意，**When** 用户点击一键确认，**Then** 应用保存当前确认版本，并进入音乐生成/推荐的下一阶段入口或明确的等待占位状态。
4. **Given** 修正请求失败，**When** 用户查看结果，**Then** 页面保留上一个有效版本，并提供重试或继续确认的选择。

### Edge Cases

- 用户尝试选择 0 张照片、超过 9 张照片或包含无法读取的文件时，页面阻止继续并说明可接受的数量或文件问题。
- 用户选择重复照片时，页面不会静默产生重复预览；应保留一次并提示，或明确允许重复后保持数量准确。
- 照片方向、尺寸或加载时间不同，预览区域仍保持稳定布局，失败的单张照片可被移除或替换。
- 用户在 Agent 处理中快速重复点击继续、确认或修正时，不产生重复请求、重复结果或状态错乱。
- 用户在确认前刷新或离开创建页后返回时，已选照片、故事、理解结果和修正内容均清除；页面不得将这些临时内容误认为已保存的音乐相册。
- 真实记忆理解服务不可用、超时或返回部分字段时，页面显示可理解的错误状态；演示模式下仍可走通同一用户流程，不阻断返回和重新选择。
- 理解结果没有事件标题，或事件与氛围均未识别时，页面将结果视为不可用，保留照片和故事供用户重试或补充，不开放确认。
- 修正后标题、氛围与时间线出现冲突时，页面保留最新有效版本并标示当前版本，不展示互相矛盾的多个“最终”结果。

## Requirements

### Functional Requirements

- **FR-001**: 创建流程 MUST 允许用户选择至少 1 张且最多 9 张照片，并在继续前显示当前选择数量。
- **FR-002**: 用户 MUST 能预览已选照片、删除单张照片，并重新选择以补充或替换照片。
- **FR-003**: 创建流程 MUST 支持可选故事输入；故事为空时仍 MUST 允许仅凭照片继续。
- **FR-004**: 对照片和故事的提交 MUST 进入可识别的处理状态，并防止重复提交造成重复结果。
- **FR-005**: 记忆理解结果 MUST 展示事件标题、人物、事件、氛围和时间线五类信息；未能识别的字段 MUST 标为“未识别”，不得臆造内容。可确认的结果 MUST 有事件标题，且事件或氛围至少有一项可用。
- **FR-006**: 页面 MUST 清楚区分初始、处理中、成功和失败四种状态，并为失败状态提供重试、重新选择或安全返回路径。
- **FR-007**: 用户 MUST 能通过自然语言提交对标题、人物、事件、氛围或时间线的修正，并看到修正处理中与完成后的结果。
- **FR-008**: 无法识别或为空的修正输入 MUST 不覆盖当前有效理解结果，并向用户说明需要补充内容。
- **FR-009**: 用户 MUST 能一键确认符合 FR-005 最低内容要求的当前理解版本，包括含“未识别”字段的部分结果；确认后 MUST 将结构化结果交给下一阶段音乐生成/推荐流程或其明确占位入口。
- **FR-010**: 修正或确认失败时，应用 MUST 保留最近一次有效结果，并提供重试或继续操作，不得显示伪造的成功状态。
- **FR-011**: 真实记忆理解能力未配置或暂时不可用时，演示模式 MUST 以稳定结果完成同一用户流程，并明确标识结果为演示内容。
- **FR-012**: 照片选择、预览、理解结果和修正交互 MUST 在移动宽度下可读可操作，不产生明显横向溢出。
- **FR-013**: 本阶段 MUST 延续 SDD-00 和 SDD-01 的页面容器、标题层级、返回行为和底部导航；不得新增登录、音乐生成、真实保存或分享能力。
- **FR-014**: 用户确认前刷新页面或离开创建页后返回时，创建流程 MUST 从初始状态重新开始，不恢复照片、故事、理解结果或修正内容。

### Key Entities

- **创建草稿**：当前一次创建流程的临时输入，包含已选照片、可选故事和当前处理状态；未确认前不代表已保存相册。
- **照片输入**：用户在本次创建中选择的单张照片，包含可展示的预览、顺序和读取状态。
- **Memory Profile**：Agent 对照片和故事形成的结构化记忆理解，包含标题、人物、事件、氛围、时间线、版本和处理状态。
- **用户修正**：用户提交的自然语言补充或修改，以及它所对应的结果版本和处理状态。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户选择 1–9 张照片后，至少 95% 的有效输入可在 10 秒内显示完整预览和准确数量。
- **SC-002**: 在固定演示数据下，至少 90% 的首次使用者能在 3 分钟内完成“选择照片 → 查看理解 → 确认”流程。
- **SC-003**: 成功理解结果中，标题、人物、事件、氛围和时间线五类信息的展示覆盖率达到 100%；达到最低内容要求时，缺失字段均标为“未识别”且不阻止确认。
- **SC-004**: 处理成功、失败、超时和修正失败四类状态均能被评审者识别，且每类状态都有可执行的下一步或安全返回路径。
- **SC-005**: 用户提交自然语言修正后，90% 的演示请求能在 15 秒内显示更新结果或明确失败反馈，且原有效版本可恢复。
- **SC-006**: 在至少 3 个常见移动视口宽度下，照片选择、修正输入、一键确认和返回操作均无明显横向滚动并保持可操作。
- **SC-007**: 在真实记忆理解能力不可用的演示环境中，100% 的核心演示步骤仍可完成，且演示结果有明确标识。

## Assumptions

- 本阶段承接 SDD-00 的创建路由和 App Shell，以及 SDD-01 的页面容器与演示数据约定。
- 照片输入以常见移动端图片为主；文件格式、大小和读取失败提示采用项目现有上传约定，未定义专门的云端存储策略。
- 记忆理解结果的五类必需信息以本规格为准；真实能力尚未接入时，演示模式提供同等可见内容。
- 用户修正默认只影响标题、人物、事件、氛围和时间线等理解字段，不在本阶段直接生成音乐或修改照片内容。
- 一次创建流程只维护一个当前草稿和一个有效理解版本；版本历史和并行草稿属于后续工作台或持久化阶段。
- 创建草稿仅在当前打开的创建流程中有效；确认后交给下一阶段的结果不受确认前草稿清除规则影响。
- 用户主要通过移动宽度使用；网络异常、Agent 超时和部分结果由页面状态处理，不影响退出和重新选择。

## Out of Scope

- AI 配乐生成、QQ 音乐检索、播放控制和沉浸式播放。
- 真实数据持久化、用户认证、照片云端存储和跨设备恢复。
- 自动事件归档、多人协作、复杂照片编辑、歌词生成和分享链接。
- Agent 内部工作台、prompt/loop/skill/tool 版本管理和运行记录对比。
