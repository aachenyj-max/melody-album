# 内部试用记录

用于 Q5 / SC-007 / T045。当前实际参与人数为 **0**，尚未验证操作时间。下方流程和空白 CSV 是待执行材料，不是验收结果。

## 组织者准备

1. 保持本地服务运行，打开 `http://localhost:3000/internal/agent-workbench`。尚未部署时，10 位试用者可轮流使用这台电脑；其他电脑上的 localhost 指向各自电脑。
2. 使用本地 `.env.local` 中的内部口令登录，准备一张允许用于内部测试的照片。不得把口令或照片内容写入试用记录。
3. 创建一条对照运行，故事填写“海边日落时，和朋友散步”，等待六阶段完成，记录其 ID。先记录当前配置和来源；当前验收预览为真实 Qwen/ACE-Step，QQ mock。如使用独立 demo 环境，必须注明演示结果不能代表真实照片理解。不要为了试用修改共享预览的全局配置。
4. 每位参与者使用匿名编号 P01–P10。计时人记录实际操作时间与等待时间，不能用脚本、同一人重复十次或预估值替代十位参与者。

## 每位参与者执行

1. 选择照片，故事填写“毕业后第一次重聚，一起回到校园”，查看配置，提交。
2. 在详情中找到六阶段、理解结果和来源标记。
3. 使用默认的“当前配置”手动重跑，确认获得新的 ID，原记录仍可查看。
4. 返回列表，选择自己的新运行和组织者准备的对照运行，进入对比。
5. 指出一个具体差异，例如 input 的故事或 memory 的 event。计时人核对实际页面是否显示该差异。

每次填写 [trial-results.csv](trial-results.csv) 一行。`active_seconds = elapsed_seconds - waiting_seconds`；等待指服务生成、上传或加载期间无法继续操作的时间。求助耗时计入操作时间，失败也保留一行及原因，不挑选样本。

## 判断与归档

- 至少 10 位不同参与者；至少 9 位完成流程、指出实际差异且 active_seconds ≤180，才通过 SC-007。
- CSV 只保留匿名编号、日期、运行 ID、计时、是否完成、差异字段与简短问题；不写姓名、故事正文、照片、口令或密钥。
- 完成后将实际人数、通过人数、耗时范围及问题记录更新至 us3.md；不足人数继续标“未验证”。若发现界面问题，修复后记录受影响项目的复验。

CSV 当前仅有表头，样本数仍为 0。
