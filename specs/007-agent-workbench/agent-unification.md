# 工作台与用户端 Agent 统一

2026-10-08；本地实现与验证完成。线上既有部署尚未包含本次改动，不能据此修改既有部署证据或宣布正式用户已使用真实理解。SDD-06 真人样本仍为 0。

## 需求与实现

- 保留一个 GitHub 仓库 `aachenyj-max/melody-album`，工作台与用户端共用 `lib/agent/config.ts`、`lib/agent/pi-runtime.ts` 的提示词、图片模型、工具校验和执行预算。
- 用户端 `/api/memory/understand` 与 `/api/memory/revise` 已替换独立规则适配器，使用同一个 Pi 执行器。修正携带上一版理解和本次指令，成功后版本加一，失败时界面保留上一版。
- 工作台自动理解和对话意图整理仍调用该执行器；对话已有音乐版本时携带上一版理解进行修正。自由讨论、运行持久化和六阶段展示属于工作台包装，用户端仍按 02→03→04 流程交互。
- 音乐意图转换、ACE-Step 生成和 QQ mock 原本已共用对应的 `lib/music/` 实现，本轮保持其配置语义。工作台选择 demo 配乐时不能将其结果视为用户端真实音乐验收。
- 提示词、模型、工具、图片及故事均为服务端任务输入；公开响应只包含理解结果和版本/模式/摘要，不返回内部提示词、日志或密钥。不经内部接口调用，不要求用户输入工作台口令，不创建内部测试记录。
- 理解仍限 45 秒、最多 3 轮、每轮最多 2048 tokens；真实调用或配置失败明确报错，不静默回退。原工具 v1 和 v2 历史快照继续支持。

## 试验与发布

工作台新测试使用当前试验版本；用户端按服务端 `USER_AGENT_CONFIG_VERSION` 固定读取版本，默认 `0` 是代码中的基线。正整数读取现有 `agent_workbench_config_versions` 的对应行，不读取 `active` 草稿。缺少该版本或读取失败会报错，不自动采用最新版本。此轮没有新增或修改数据库结构。

1. 在工作台“编辑工作台配置”里修改提示词或指令，点击“保存为新版本”，记下版本号。
2. 使用新版本测试照片、理解和修正，与基线对比。现有历史运行保持创建时的配置。
3. 在正式发布前，将用户端测试环境的 `USER_AGENT_CONFIG_VERSION` 指向该版本号，设置 `USER_AGENT_MODE=live`，并部署待发布代码。该环境必须使用相同 Supabase 项目，以及与工作台相同的 Pi/Qwen 供应商、模型和协议配置。密钥只放部署 Secret。
4. 使用用户端完成上传→理解→修正→确认。公开理解响应的 `agent.digest` 应与工作台配置响应的 `memoryDigest` 相同；该摘要覆盖模型、提示词、技能、工具、Loop 与记忆契约，排除独立的配乐模式。模型输出具有随机性，相同摘要不保证逐字相同结果。
5. 验证通过后，再将正式用户端的固定版本切到该编号，并部署同一套已验证代码。保存工作台新草稿不会自动更改正式环境。
6. 需要回退时，恢复前一版本号和对应已验证代码、模型配置，重新部署。每次发布记录代码版本、配置号及摘要。

`USER_AGENT_MODE` 可独立设为 `demo` 或 `live`；未设置时沿用显式 `PI_EXECUTION_MODE`，两者均未设置才默认 demo，已有 key 不触发自动切换。用户端理解不依赖 `WORKBENCH_MUSIC_MODE` 或 FAL key。工作台“本环境用户端”提示只描述当前部署，不能据此推断另一个 Vercel 项目的设置。

新增环境变量后需重启本地服务或重新部署 Vercel。用户无需手动管理密钥；试验通过后可告知 Codex“将工作台配置版本 N 同步到用户端”，由 Codex核对摘要、代码、目标环境和验证记录后执行发布。
