## Clarifications

### Session 2026-10-05

- Q: 内部 Agent 工作台需要在哪些环境开放，内部人员如何进入？ → A: 本地和部署环境均可开放，使用独立内部访问口令；未配置口令时关闭工作台及相关操作。
- Q: 测试运行记录及用于重跑的照片、故事需要保留多久？ → A: 持久保留 30 天，刷新和服务重启后仍可查看、重跑；到期清理。
- Q: 手动重跑同一组照片和故事时，应该使用哪个配置版本？ → A: 默认使用当前配置，也可选择原运行的配置版本；新记录注明实际使用版本，不增加在线配置编辑功能。

### Session 2026-10-06

- Q: 工作台完成照片的记忆理解后，是否需要人工确认才能继续生成配乐和推荐歌曲？ → A: 自动继续，以本次记忆理解结果生成配乐和推荐；明确标记为内部测试，用户端仍保留人工确认流程。

## User Scenarios & Testing

### User Story 1 - 发起一次可追踪的测试运行 (Priority: P1)

内部人员进入独立的 Agent 工作台，选择一组测试照片并补充可选故事，查看本次运行使用的 prompt、loop、skill、tool 配置版本，然后发起测试运行。记忆理解成功且结果有效后，工作台自动继续形成音乐意图、生成配乐和获取推荐，不等待人工确认。运行完成后，工作台按阶段展示输入、记忆理解、音乐意图、工具调用和最终结果，帮助内部人员判断整条 Agent 链路是否按预期工作；全过程标记为内部测试。

**Why this priority**: 工作台首先要让内部人员看见一次完整运行，才能定位用户端主流程中的理解、编排或工具调用问题；可追踪性是其区别于普通演示页的核心价值。

**Independent Test**: 使用 1–9 张测试照片和一段故事发起一次运行，确认运行获得唯一标识、配置版本被记录，并能在同一工作台看到完整的中间结果和最终状态；该测试不依赖用户端导航。

**Acceptance Scenarios**:

1. **Given** 内部人员已打开工作台并选择了有效测试照片，**When** 发起运行，**Then** 工作台显示运行状态、输入摘要、所用配置版本和可追踪的运行标识。
2. **Given** 一次运行已经完成，**When** 内部人员查看运行详情，**Then** 页面按顺序展示 Memory Profile、Music Profile、工具调用、工具返回结果和最终汇总，并明确标识成功、失败或未完成的阶段。
3. **Given** 测试故事为空但照片数量有效，**When** 内部人员发起运行，**Then** 运行仍可开始，并在详情中标明故事未提供。
4. **Given** 本地或部署环境未配置内部访问口令，或访问者未通过口令验证，**When** 访问工作台页面、运行记录或发起运行与重跑，**Then** 访问被阻止，不返回测试数据，也不触发 Agent 或音乐工具调用。
5. **Given** 本次记忆理解成功并返回有效结果，**When** 理解阶段完成，**Then** 系统自动基于该结果执行音乐编排、配乐生成和推荐，无需点击确认；输入、运行记录和结果均标记为内部测试，不修改用户端的确认规则或保存相册。
6. **Given** 本次记忆理解失败或结果无效，**When** 理解阶段结束，**Then** 后续音乐阶段标记为跳过并说明原因，不使用历史或伪造的理解结果继续运行。

### User Story 2 - 重跑并保留历史版本 (Priority: P1)

内部人员可以使用同一组输入再次运行 Agent，以验证配置或供应商结果的变化。重跑默认使用当前配置，也可选择原运行的配置版本；运行前显示选择，运行后记录实际版本。每次重跑都产生新的运行记录，旧记录仍可打开，且结果不会被覆盖。

**Why this priority**: Agent 行为需要通过重复实验比较；如果重跑覆盖历史结果，内部人员无法判断变化来自输入、配置还是外部工具。

**Independent Test**: 打开一条已完成运行，执行一次手动重跑，确认生成新的运行记录，原记录的配置、状态和中间结果仍保持不变，并可分别打开两条记录。

**Acceptance Scenarios**:

1. **Given** 已存在一条未到期的成功、失败或未完成运行，**When** 内部人员点击“手动重跑”并保留默认配置选择，**Then** 系统使用该运行的输入快照和当前配置创建新的运行记录，记录实际配置版本，并在列表中区分新旧记录。
2. **Given** 重跑正在进行，**When** 内部人员返回并打开旧记录，**Then** 旧记录仍显示原始配置、阶段状态和结果，不被新运行的进度替换。
3. **Given** 重跑失败，**When** 内部人员查看结果，**Then** 新记录显示失败阶段和可理解的错误摘要，旧记录仍可正常查看。
4. **Given** 一条运行记录创建未满 30 天，**When** 内部人员刷新页面或在服务重启后重新访问，**Then** 仍能打开原记录并使用保留的照片、故事快照重跑。
5. **Given** 一条运行记录已满 30 天，**When** 内部人员访问或尝试重跑，**Then** 系统提示记录已过期或不存在，不返回旧输入或结果；可重新提交测试输入创建新记录。
6. **Given** 原运行配置版本仍可执行，**When** 内部人员选择原版本重跑，**Then** 新记录使用原配置快照并记录该版本；若原版本不可执行，则显示原因并阻止这次重跑，不静默改用当前版本。

### User Story 3 - 对比运行结果并保护用户端链路 (Priority: P2)

内部人员可以选择两条运行记录进行对比，快速看到输入、配置版本、Memory Profile、Music Profile、工具调用和最终结果的差异。工作台出现异常时，用户端上传、理解、生成、播放和保存流程仍保持可用。

**Why this priority**: 对比能力能把一次性排查变成可复用的质量判断；与用户端隔离则保证内部诊断能力不会成为 MVP 主链路的单点故障。

**Independent Test**: 选择两条不同配置或不同输入的运行记录，验证差异可读；再让工作台运行失败或不可访问，确认用户端核心入口仍可使用且不显示内部错误详情。

**Acceptance Scenarios**:

1. **Given** 工作台中有两条可访问的运行记录，**When** 内部人员选择并对比它们，**Then** 页面按输入、配置、Profile、工具调用和最终结果分组展示相同项与差异项，并标明缺失或未完成部分。
2. **Given** 两条记录使用相同输入但不同配置版本，**When** 内部人员查看对比，**Then** 配置版本差异清晰可见，旧记录内容仍保持只读。
3. **Given** 工作台服务或单次运行出现异常，**When** 用户访问用户端主流程，**Then** 用户端仍能进入既有页面；工作台错误不会进入用户端导航、文案或数据展示。

### Edge Cases

- 未选择照片、照片数量超过 9 张或测试文件无法读取时，禁止发起运行并指出需要修正的输入。
- 测试故事为空时允许仅凭照片运行；故事超过已有输入契约允许的长度或格式无效时，保留照片和故事输入并提示修正，阻止提交，不静默忽略故事。
- 运行在任一阶段超时、被取消或返回部分结果时，记录已完成阶段，标记未完成阶段，不伪造最终成功。
- prompt、loop、skill 或 tool 配置缺少版本、版本不可用或读取失败时，运行不得静默使用未知配置；应显示配置不可用并允许返回或重试。
- 原配置引用的工具或供应商能力已不可用时，原版本重跑显示不可执行原因；内部人员可另行选择当前配置重跑，旧记录仍可查看，不承诺复现外部供应商的历史输出。
- 工具返回空结果、格式错误或部分成功时，保留调用状态和错误摘要；依赖该结果的后续阶段明确失败或跳过，不影响独立分支。AI 配乐失败仍保留推荐结果，推荐失败仍保留 AI 配乐结果。
- 记忆理解失败或结果无效时不继续音乐阶段；真实、演示和 mock 来源分别标记，不把内部自动继续标作用户已经确认。
- 同时发起多次运行时，每次运行都必须有独立记录，互不覆盖输入、状态或结果。
- 运行记录不存在、无权访问或已被清理时，显示找不到记录，不泄露其他记录的内容。
- 运行记录从创建时间起保留 30 天；到期后不可查看、对比或重跑，并清理对应的输入和结果。重跑创建的新记录按自己的创建时间计算 30 天，不延长旧记录的期限；共享测试照片时，不得因旧记录清理而破坏仍在保留期内的新记录。
- 未配置内部访问口令时，工作台页面及全部相关读取、运行、重跑和对比操作均关闭；用户端主流程保持原有行为。
- 窄屏、较大系统字体和键盘操作下，运行列表、详情、对比区域和主要按钮仍可读可操作。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供独立的内部 Agent 工作台入口；该入口 MUST 不出现在用户端底部导航、首页入口或 01–09 号用户端流程中。
- **FR-002**: 工作台 MUST 允许内部人员提交 1–9 张测试照片和可选故事，并在运行前显示输入摘要；无效输入 MUST 阻止运行并给出具体修正提示。
- **FR-003**: 每次运行 MUST 记录可追踪的运行标识、开始时间、结束时间或当前状态、输入摘要和所使用的 prompt、loop、skill、tool 配置版本。
- **FR-004**: 工作台 MUST 展示运行阶段的状态，至少覆盖输入、Memory Profile、Music Profile、工具调用、工具返回结果和最终汇总；每个阶段 MUST 明确标记成功、失败、未完成或跳过。
- **FR-005**: Memory Profile MUST 展示本次运行产生的人物、事件、氛围、时间线和标题等可用字段；缺失字段 MUST 显示为空或未提供，不得使用另一条运行的数据补齐。
- **FR-006**: Music Profile MUST 展示本次运行的音乐意图、AI 配乐状态和 QQ 音乐推荐状态；结果只有元信息、不可播放或生成失败时 MUST 保留真实状态。
- **FR-007**: 每次工具调用 MUST 展示调用名称、调用阶段、请求摘要、返回状态、结果摘要和错误信息（如有）；展示内容 MUST 避免暴露服务端密钥、访问凭证和不必要的原始隐私数据。
- **FR-008**: 工作台 MUST 支持对未到期运行执行手动重跑，使用原输入快照并默认选择当前配置；内部人员 MUST 可改选原运行的配置版本。发起前 MUST 展示所选版本，新记录 MUST 保存实际执行的版本与配置快照及原运行关联，不得覆盖原运行的输入、配置、状态或结果。所选版本不可执行时 MUST 明确阻止重跑，不得静默切换版本。
- **FR-009**: 工作台 MUST 支持选择两条运行记录进行对比，并按输入、配置版本、Memory Profile、Music Profile、工具调用和最终结果展示差异。
- **FR-010**: 运行记录 MUST 支持按时间、状态和运行标识查看与打开；打开旧记录时显示其当时的配置和阶段结果，而不是当前默认配置。
- **FR-011**: 运行失败、超时、取消或部分完成时，系统 MUST 保存已完成阶段和可理解的失败摘要，并提供重试、重跑或返回入口；不得显示伪造的完整成功。
- **FR-012**: 工作台异常、无数据或暂时不可访问时，用户端主流程 MUST 继续保持既有可达页面和行为；工作台 MUST 不改变用户端导航和用户端演示数据。
- **FR-013**: 工作台 MUST 在本地和部署环境使用独立内部访问口令限制访问；未配置口令时 MUST 关闭工作台页面及相关读取、运行、重跑和对比操作。全部操作 MUST 验证内部访问资格；未经验证的访问 MUST 不返回记录内容、不触发工具调用。未知或已删除记录 MUST 返回找不到状态。
- **FR-014**: 运行记录及其对比视图 MUST 保留历史版本之间的只读边界；任何重跑、查看或对比操作 MUST 不修改已完成运行的内容。
- **FR-015**: 工作台的主要布局、信息层级、状态文案和操作反馈 MUST 服务于内部诊断，不得冒充 01–09 号用户端设计稿；用户端导航中不得加入工作台入口。
- **FR-016**: 系统 MUST 从每条运行记录的创建时间起持久保留 30 天，保留内容包含用于重跑的测试照片、故事输入快照、配置快照、各阶段结果和工具调用记录；刷新和服务重启 MUST 不导致这些内容丢失。到期后 MUST 禁止查看、对比和重跑，并清理相应数据；清理 MUST 不影响其他仍在保留期内的记录。重跑产生的新记录 MUST 独立计算保留期限，不得续期或修改旧记录。
- **FR-017**: 新测试运行及手动重跑 MUST 在记忆理解成功且结果有效后自动进入音乐意图、配乐生成和推荐阶段，不等待人工确认；理解失败或无效时 MUST 跳过依赖它的音乐阶段并记录原因。配乐与推荐 MUST 按既有编排契约独立记录结果，单路失败不得清除另一条分支的有效结果。
- **FR-018**: 工作台 MUST 将输入、运行及结果明确标记为内部测试，并在各阶段及对比中区分真实、演示或 mock 来源；内部自动继续 MUST 不代表用户确认，不修改用户端确认流程，不自动写入用户的音乐相册。

### Key Entities

- **Agent 运行记录**：一次测试运行的历史快照，包含运行标识、内部测试标记、原运行关联（重跑时）、输入摘要、状态、时间、配置版本、各阶段来源和结果；创建 30 天后到期清理，保留期内的已完成内容不可被重跑覆盖。
- **测试输入集**：本次运行使用的有序照片和可选故事，包含数量、读取状态和输入摘要。
- **配置版本**：运行时使用的 prompt、loop、skill、tool 配置快照及版本标识，用于重跑和对比；重跑可选择当前配置或原运行快照，记录实际选择，不保存供应商访问凭证。
- **Memory Profile**：Agent 对照片与故事形成的记忆理解结果，包含人物、事件、氛围、时间线和标题等字段。
- **Music Profile**：由记忆理解形成的音乐意图与生成/推荐结果状态，包含 AI 配乐和 QQ 音乐推荐的摘要。
- **工具调用记录**：一次工具调用的名称、阶段、请求与返回摘要、状态、错误和时间。
- **运行对比**：两条运行记录的只读差异视图，包含相同项、变化项和缺失项。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 内部人员使用有效测试输入发起运行后，至少 95% 的完整运行可在 10 秒内看到运行标识、配置版本和当前阶段状态。
- **SC-002**: 在 10 次包含有效照片的测试运行中，10 次都能在详情中找到 Memory Profile、Music Profile、工具调用和最终汇总的状态；失败运行也能看到失败阶段。
- **SC-003**: 对同一输入连续执行 10 次手动重跑，最终产生 10 条可区分的运行记录，原始记录的内容均保持不变。
- **SC-004**: 内部人员对两条运行记录进行对比时，至少 95% 的配置差异、Profile 差异和工具状态差异可在同一视图中被识别，无需打开源码或日志文件。
- **SC-005**: 工作台发生不可用或单次运行失败时，用户端主流程的 5 个核心入口（上传、理解、生成/推荐、播放、保存）仍保持可访问，且用户端不展示内部错误细节。
- **SC-006**: 100% 的未授权或未知运行记录访问尝试不返回照片内容、故事原文、音频地址、凭证或其他运行结果。
- **SC-007**: 在不计 Agent 与音乐工具等待时间的情况下，至少 90% 的内部人员可在累计 3 分钟操作时间内完成“提交测试运行 → 查看中间结果 → 重跑 → 对比两条记录”的任务，并能指出一次配置或阶段状态差异。
- **SC-008**: 在本地和部署环境分别验证未配置口令、未验证访问和错误口令三种情况，100% 的页面、记录读取、发起运行、重跑和对比操作均被阻止，且不触发 Agent 或音乐工具调用。
- **SC-009**: 对 10 条未满 30 天的运行记录，在刷新及服务重启后，10 条均可读取原输入和结果并发起重跑；对已到期记录的查看、对比和重跑均被阻止，清理不会破坏仍在保留期内的记录。
- **SC-010**: 对同一输入分别使用当前配置和可执行的原配置重跑，100% 的新记录注明实际版本且旧记录不变；原配置不可执行时，100% 的尝试显示原因，不生成冒充原版本的结果。
- **SC-011**: 在有效理解、理解失败、AI 配乐失败和推荐失败四类测试中，所有有效理解均无需人工确认即可进入音乐阶段，所有无效理解均不调用后续音乐工具，单路失败均不覆盖另一分支结果；所有记录标记为内部测试并注明各阶段来源，用户端确认与保存行为保持不变。

## Assumptions

- “第 6 阶段”指 `docs/音乐相册-MVP分阶段开发部署规划.md` 与 `progress.md` 中的 SDD-06「内部 Agent 工作台」，不是用户端第 06 张“调整音乐 · Agent 对话页”设计稿。
- 工作台面向持有独立内部访问口令并通过验证的项目成员，本地和部署环境均可开放；未配置口令时关闭。本阶段只提供必要的内部口令验证入口，不新增用户端登录、注册或账户管理页面。
- 工作台运行使用项目已有的 Agent、记忆理解和音乐编排契约；本阶段关注可观察、可重跑和可对比，不重新定义用户端 Agent 业务流程。
- 本阶段按用户补充要求基于 `https://github.com/earendil-works/pi` 接入 Agent，沿用现有 Next.js App Router、TypeScript、Tailwind CSS v4 与 Biome。大模型 API key 后续提供；当前采用明确标记的同契约演示模式，真实模式缺少或无效凭证时必须报错，不得静默回退为演示结果。
- 工作台测试自动执行理解到生成/推荐的链路，不提供运行中的人工修正和确认环节；用户端人工确认仍由 SDD-02 负责。工作台只处理内部提交的测试输入，不自动收集用户端运行或保存测试结果为用户相册。
- 各阶段沿用已有的真实接口或同契约演示适配器，推荐沿用当前明确标识的 mock 来源；凭证缺失不阻断契约内的演示验收，但演示结果不计为真实供应商验收。
- 当前配置由项目既有发布方式更新；工作台只选择当前配置或原运行快照，不提供在线配置编辑或发布。原版本重跑复用当时的配置，但不保证外部工具返回与历史结果相同。
- 测试照片和故事可以来自本地演示输入或项目允许的内部测试数据；数据展示应遵守现有隐私和密钥边界。
- 运行记录默认按创建时间倒序展示，状态、运行标识和配置版本可用于定位；具体筛选和分页方式留给后续计划确定。
- 运行记录及所需测试输入持久保留 30 天，从每条记录创建时间起计算，到期清理；具体清理执行方式和并发上限在后续计划中确定，不得因清理或并发异常覆盖历史记录或破坏未到期记录。

## Out of Scope

- 将工作台加入用户端首页、底部导航或 01–09 号设计稿流程。
- 用户端照片上传、记忆理解、音乐生成、播放、保存和分享能力的重新实现。
- 面向普通用户的 Agent 调试、配置编辑、供应商凭证管理和权限管理后台。
- 直接修改 prompt、loop、skill、tool 内容或在线发布配置；本阶段只展示运行时使用的版本并支持重跑、查看和对比。
- 已保存音乐相册的编辑、删除、多人协作和真实分享。
- 以工作台结果替代用户端真实业务结果，或将演示适配器结果宣称为真实供应商结果。
