# 音乐相册 MVP 分阶段开发与部署规划

## 1. 规划口径

本规划把产品方案中的需求视为产品约束，把每个阶段定义为一个独立的 Speckit SDD 单元。每个单元都应有自己的 `spec.md`、`plan.md`、`tasks.md` 和验收记录，完成后仓库保持可启动、可演示。

估算采用 AI Agent Coding 口径：一个阶段按一段连续对话完成，通常包含 3–6 个实现回合和 1 次质量检查；不是生产团队工期，也不包含等待外部 API 账号审批的时间。

建议模型等级：

- **Sol / medium**：页面、状态管理、静态数据和常规 Supabase CRUD。
- **Sol / high**：跨页面核心流程、上传、持久化和失败状态。
- **Astra / high**：外部 Agent、music API、QQ 音乐检索和部署边界等高不确定集成。

## 3. 各 SDD 单元的验收边界

### SDD-00：可运行框架与设计基线

**做什么**

- 把当前单页骨架改为音乐相册 App Shell，建立首页、创建、结果、播放、记忆列表、详情的路由或状态切换边界。
- 统一页面容器、底部导航、颜色/字体/间距 token，并把 9 张设计稿映射到 5 类页面和状态。
- 保留当前 Next.js、Tailwind v4、Biome、Supabase 客户端，不引入新框架。
- 用只读连接校验确认 Supabase 环境可用，定义后续表和 Storage bucket 的命名约定，但不在本阶段做业务写入。

**独立验收**：`npm run dev` 可启动；每个页面入口可到达；移动宽度下无明显溢出；`npm run tscheck`、`npm run lint` 通过。

### SDD-01：首页与历史记忆

**做什么**

- 首页首屏突出“上传照片，生成一段记忆”。
- 用本地 mock 数据展示最近音乐记忆、最近 AI 配乐、列表和详情。
- 探索/推荐、个人中心只做不可用占位入口；分享按钮只显示，不实现分享。

**独立验收**：从首页能打开列表和详情；mock 相册有封面、标题、照片、歌曲和日期；刷新后仍能看到稳定演示数据。

### SDD-02：Agent 创建与记忆理解

**做什么**

- 支持 1–9 张照片的选择、预览、删除和重新选择。
- 支持可选故事输入；只上传照片也能进入记忆理解状态。
- 接入或封装 Pi Agent 的 Memory Profile 返回结构，展示人物、事件、氛围、时间线和标题。
- 支持一键确认与自然语言修正，修正后能重新展示理解结果。

**独立验收**：用测试照片完成“上传 → 理解 → 修改 → 确认”；超出 9 张有明确提示；Agent 失败时有可继续的错误状态。

### SDD-03：音乐结果编排与等待兜底

**做什么**

- 将确认后的 Memory Profile 转为 Music Profile。
- 并列展示 AI 无歌词配乐和 QQ 音乐推荐；主链路调用真实接口/工具，mock 只作开发回退或历史展示。
- 个性化配乐生成期间先播放通用氛围音乐，显示轻量进度；完成后替换音源。
- 原创生成失败时保留 QQ 音乐结果，并允许继续播放和保存。

**独立验收**：成功、慢响应、失败三种状态均可演示；至少能看到一条 QQ 音乐推荐和一条 AI 配乐状态；失败不阻断后续页面。

### SDD-04：沉浸式播放与调整

**做什么**

- 实现照片缓慢切换、播放/暂停、进度和退出。
- AI 解释默认收起；提供“调整音乐”对话入口。
- 接收“更快乐一点”“更安静一点”等指令并重新请求 Music Profile/生成结果。

**独立验收**：进入播放页后照片和音乐可同时开始；调整后有明确的生成中、成功或失败状态；不依赖保存动作也能完整播放。

### SDD-05：保存音乐相册与 Supabase 数据

**做什么**

- 设计并创建最小 Supabase 表/Storage：相册、照片、音乐版本、推荐歌曲、生成运行记录。
- 保存事件标题、照片组、AI 配乐、QQ 音乐推荐、用户一句话、创建日期和事件时间。
- 保存成功后回到详情；失败时保留当前结果并给出重试。
- 将 SDD-01 的 mock 列表逐步切换为真实读取，同时保留无数据时的演示空状态。

**独立验收**：从一次已生成结果保存后，刷新并重新打开仍可看到同一相册；原创音乐失败时仍能保存 QQ 音乐结果；未登录演示策略符合最终决策。

### SDD-06：内部 Agent 工作台

**做什么**

- 只提供内部路径，不加入用户端导航和 9 张用户设计稿流程。
- 展示 prompt、loop、skill、tool 配置版本，以及测试照片/故事运行记录。
- 查看 Memory Profile、Music Profile、工具调用和结果；支持手动重跑与版本对比。

**独立验收**：内部人员能用一组测试照片运行一次，并看到完整中间结果；重跑不会覆盖旧记录；用户端主流程不受工作台异常影响。

### SDD-07：MVP 验收、硬化与上线

**做什么**

- 按 Demo 剧本跑通真实照片主链路，补齐加载、空状态、失败和返回行为。
- 执行 `npm run format`、`npm run lint`、`npm run tscheck`、`npm run build`。
- 配置 Vercel/目标托管环境变量：浏览器只使用 `NEXT_PUBLIC_SUPABASE_URL` 和 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`，服务端密钥保持服务端。
- 记录部署地址、验证步骤、已知限制和回滚方式。

**独立验收**：线上环境能完成上传、理解、生成/推荐、播放、保存；原创失败仍可保存；不暴露服务端密钥；构建和静态检查通过。

## 4. 已确认的实现前提

以下三项已确认，后续 SDD 直接按此设计，不再重复讨论。

### Q1：Agent 与音乐接口当前是否已有可调用地址和凭证？（SDD-02/03）

| 选项 | 做法 | 影响 |
|---|---|---|
| A（已确认） | 先把真实接口的输入/输出字段和错误码定下来；无凭证时用同契约的本地适配器 | 主链路不被账号等待卡住，后续替换成本最低 |
| B | 等真实接口全部开通后再开发 | 真实度高，但会让 UI 和流程开发停滞 |
| C | 本次只做本地模拟 | 最快，但不满足方案中“Demo 主链路使用真实 API/tool” |

### Q2：MVP 是否需要登录？（SDD-05）

| 选项 | 做法 | 影响 |
|---|---|---|
| A（已确认） | Demo 优先采用 Supabase 匿名会话；若项目尚未开启匿名登录，则由服务端使用固定演示用户标识作为回退，数据按用户标识隔离 | 能验证保存和刷新，避免把 Auth 页面引入 MVP |
| B | 接入 Supabase Auth 登录 | 数据边界最完整，但增加一段非核心流程 |
| C | 全部只存在浏览器 | 实现最快，但无法证明“保存后再次打开” |

### Q3：Supabase Storage 是否作为正式照片存储？（SDD-05）

| 选项 | 做法 | 影响 |
|---|---|---|
| A（已确认） | 使用私有 Storage bucket 保存照片，数据库保存路径和元数据；详情读取时生成短时访问地址 | 最接近产品真实形态，详情页可稳定重载 |
| B | 本地/浏览器预览，数据库只保存文本 | 开发更快，但刷新后照片不可恢复 |
| C | 先用公开 URL | 验证快，但不适合私有音乐相册默认权限 |

## 5. 推荐的执行顺序与停止点

1. 先完成 SDD-00 和 SDD-01，形成可点击、可展示的 App 外壳。
2. 完成 SDD-02 后，确认照片理解结果和中文文案是否符合预期；不满意就在这里调整，不要继续堆音乐能力。
3. 完成 SDD-03 和 SDD-04，得到可播放的情绪命中 Demo。
4. 完成 SDD-05，才宣布“用户可保存的 MVP”完成。
5. SDD-06 可并行于 SDD-05 的后半段，但上线前必须确保它不进入用户导航。
6. SDD-07 只处理验收、配置和部署，不在此阶段追加新产品功能。

## 7. 本次 MVP 的最终交付判断

当且仅当以下链路在目标部署环境完整通过，才认为 MVP 完成：

```text
上传 1–9 张照片
→ Agent 生成并允许修正 Memory Profile
→ 同时得到 AI 配乐状态和 QQ 音乐推荐
→ 通用氛围音乐等待并能无缝切换
→ 沉浸式播放和自然语言调整
→ 即使原创失败仍可保存
→ 刷新后在我的音乐记忆中看到详情
```

歌词版、真实分享、自动事件归档、多人共创、年度记忆和完整原创歌曲全部留到后续 SDD，不作为本次上线阻塞项。
